# doc-filing · 文档归位与命名

**规则唯一真源是 [`docs/文档规范.md`](../../../docs/文档规范.md)。本 skill 不留任何规则副本**——只是「开工前先读它、按它落位」的强制入口。

> 为什么这么死板：这套规则曾经在仓里有 3 份副本并且打架（治理「三篇」vs「两篇」、词表漏 4 类、ADR 枚举停在 0010）。现在由 `python check_docs.py --check`（CI 硬门）盯着，**本文件里若长回规则正文，门禁会直接红**。

## 何时用
- 要在 `docs/` 下新建一篇 md（设计说明 / 评审 / 操作指南 / 选型调研 / 路线图 / 复盘 / 方案 …）。
- 要整理、移动、重命名、删除已有项目文档。

## 三步
1. **先读** [`docs/文档规范.md`](../../../docs/文档规范.md)：§3 决策表判品类 → §2 词表定目录和名字 → §4.0 三问确认这篇该不该存在。
2. **按 §4.1 五步写**：定性质 → 定名字 → 先画图（非免图档）→ 写正文（§4.2 骨架、§4.3 红线）→ 登记。
3. **收尾自查**：
   ```bash
   python check_docs.py          # 索引/命名/副本/行长四项，报告模式
   ```

## 红线
- **不复制规则**。要引用规矩就写指针（「见 `docs/文档规范.md` §N」），不抄正文。
- 不把实施计划塞进 `docs/`（那走 `.claude/plan/<task>.md`），反之亦然。
- 改了归属或命名规则 → **先改 `docs/文档规范.md`**，别处只跟着改指针。
