## 这是什么

两项刻意练习，练的都是"先判断、后核验、定期回看偏差"这个闭环，不是单纯记流水账：

1. **预测-验证卡片**：遇到判断点（代码会不会出问题、AI 给的答案对不对、这个方案靠不靠谱），先写下预测和理由，再看实际结果，记录偏差在哪。
2. **决策日志**：做技术决策时记下决策本身和关键假设，定期回顾这些假设是否成立，隔一段时间后回看"如果重来会怎么选"。

只手动触发（`disable-model-invocation: true`），不会被模型自主联想触发，不占用日常对话的上下文。

## 调用入口与菜单

用户输入 `/judgment-practice` 且不带参数时，用 AskUserQuestion 问：

1. 记一张新的预测卡
2. 补全一张预测卡的结果
3. 记一条新的决策
4. 回顾（review）

带自然语言参数时直接解析意图跳对应分支，不用再问一遍菜单（比如"记一条决策"→ 分支 3，"review"或"回顾"→ 分支 4）。

## 分支 1：预测卡新建流程

依次追问（一次问一件事，不要一次性甩一堆字段让用户填表）：
1. "判断的问题是什么？"
2. "你的预测是什么？"
3. "为什么这么预测？"（理由）

读取 [templates/prediction-entry.md](templates/prediction-entry.md) 作为条目骨架，按当前日期时间填充 `{{DATE}}`/`{{TIME}}`。"实际结果"和"偏差在哪"两个字段先写 `_(待补)_` 占位。用 Edit 追加到 `data/predictions.md` 文件尾（同一天的记录复用同一个 `## {{DATE}}` 二级标题，条目本身是三级标题）。

写完后提示一句："记好了，等看到实际结果后回来选'2 补全预测卡'就能把结果和偏差填上。"

## 分支 2：预测卡补全流程

1. 在 `data/predictions.md` 里 grep `_(待补)_`，列出最近 3 条还没填结果的条目（时间 + 问题一句话），让用户选一条。
2. 追问"实际结果是什么？"、"偏差在哪——你觉得判断错在哪一步？"
3. 用 Edit 精确定位该条目，把"实际结果"和"偏差在哪"两行原地回填（不要新建条目，原地回填才能让预测和结果并排对照）。

## 分支 3：决策日志新建流程

依次追问：
1. "这次决策是什么？"
2. "关键假设有哪些？"（1-3 条，越具体越好，方便以后核对是否被打脸）
3. "备选方案是什么、为什么没选它？"

读取 [templates/decision-entry.md](templates/decision-entry.md) 作为骨架，填好后用 Edit 追加到 `data/decisions.md` 文件尾。"周回顾结论"和"如果重来"两个字段先写 `_(待补)_` 占位。

## 分支 4：回顾（review）

1. 读 `data/predictions.md` 文件头"上次回顾"日期：若为空显示"从未回顾过"，若距今 ≥7 天视为该回顾了。汇总本周新增条目数、已补全数、明显偏差的条目，尝试归纳一句"这段时间反复出现的判断偏差模式"（比如"高估了 AI 给代码的边界条件覆盖率"）。
2. 读 `data/decisions.md` 文件头"上次周回顾"日期（阈值 7 天）：列出"周回顾结论"还是 `_(待补)_` 的决策条目，逐条问"这个假设现在看成立吗"，得到回答后用 Edit 回填。
3. 读"上次季度回顾"日期（阈值 90 天）：若到期，问要不要挑 2-3 条较早的决策写"如果重来"，用户同意则逐条追问并回填，用户说不用就跳过，不强求。
4. 回顾流程走完后，必须用 Edit 把对应文件头的时间戳字段更新为当天日期——这是第 9 节被动提醒机制能持续生效的前提，漏了这一步会导致提醒逻辑失真。

## 每次调用都做的被动提醒（周期回顾的落地机制）

这个 skill 不接 `/schedule`，没有后台定时任务，靠"高频操作顺带检查"实现类似效果：**无论用户选的是分支 1/2/3 哪一个，在该分支操作执行完之后**，顺带读一下两个文件头部的时间戳做轻量检查（不打断当前操作，只是追加一句提醒，用户可以忽略）：

- `predictions.md` 头部"上次回顾"：为空或距今 ≥7 天 → 提醒"距上次预测回顾已 N 天，要不要顺手看看最近的偏差？"
- `decisions.md` 头部"上次周回顾"：为空或距今 ≥7 天 → 同样提醒。
- `decisions.md` 头部"上次季度回顾"：为空或距今 ≥90 天 → 提醒可以做一次"如果重来"回看。

用户选分支 4 时直接进入完整回顾（跳过这层轻量提醒，因为本身就是在回顾）。

## 边界

- 只做预测-验证卡片和决策日志这两项练习，不做事故复盘精读、code review 刻意找茬、独立的季度回顾三项（这三项以后视使用情况再扩展成新分支或新 skill）。
- 不自动 `git commit` 这两个数据文件——它们在 DailyWorkbench 仓库的 git 追踪范围内，何时提交由用户自己决定。
- 不接 `/schedule` 或任何后台定时任务，周期回顾完全靠上面"被动提醒机制"实现。
