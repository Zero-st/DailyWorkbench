# chrome-walkthrough-flow：Chrome 驱动的走查 / 联调（跨项目）

本 skill 是**方法论骨架**，与具体项目解耦。所有「登录地址、账号、数据库、切角色方式、落盘目录、角色/状态字典」等项目专属参数，一律从 `profiles/<项目>.md` 读取——**先选 profile，再干活**。

## 0. Profile 选择协议（第一步，必做）

1. 判断当前项目：看当前工作目录 / 仓库名（如 `iris-ecnu`、`egrant-zryhyy`）。
2. 读对应 `profiles/<项目>.md`（相对本 skill 目录）。它定义本次走查的：
   - `mode`：`read-only-walkthrough`（只浏览+SELECT，**绝不写**）或 `write-e2e`（含新增/提交/审核等写路径）。
   - `baseUrl` / 登录方式 / 验证码处理 / 凭据来源。
   - 数据库 MCP 与连接（只读核对用）。
   - 切角色方式、角色枚举方式。
   - 报告 / 截图落盘目录与命名。
   - 步数预算、角色/状态字典（如有）。
3. **找不到当前项目的 profile** → 停下来提示「请在 `profiles/` 下补一个 `<项目>.md`」，并给出需要的字段清单；**不要拿别的项目参数硬套**（技术栈/账号/库都不同，套错会误导或误操作）。
4. profile 里 `mode=read-only-walkthrough` 时，本 skill 下文所有「写路径」步骤**一律跳过**；只做浏览、点击导航、查看、SELECT 核对。

> 新增一个项目 profile：照 `profiles/iris-ecnu.md` 的字段结构复制一份，填成该项目的真实参数即可。

## 1. 通用方法论（按 profile 参数执行）

1. **登录**：按 profile 的登录方式进入系统；核对登录请求 2xx、无 JS 报错。
2. **确定走查范围**：调用者给了清单就照单走；没给就按「每账号 × 每角色」遍历当前可见主菜单首屏。范围大先与调用者确认优先级，别无脑全量。
3. **切角色**：按 profile 的切角色方式逐个切；切换后先等页面稳定、再确认菜单/角色已随之改变。把实测的 `角色名 ↔ roleId` 记下来备回填。
4. **逐页走查**：每到一个页面/功能：
   - `take_snapshot` 看结构（**必要时** `take_screenshot` 存证到 profile 指定目录，文件名带角色+页面）。
   - `list_console_messages` 抓 JS 报错/告警。
   - `list_network_requests` 抓 4xx/5xx/超时；可疑的用 `get_network_request` 看详情。
   - 观察：报错 / 白屏 / 数据缺失 / 布局错乱 / **权限越界（看到不该看到的数据或入口）**。
5. **（仅 `write-e2e` mode）写路径联调**：按业务主链路走 新增→提交→审核→维护，每个状态切换点直连数据库核对数据是否正确落库/流转。**`read-only-walkthrough` mode 跳过整步。**
6. **数据库核对**：用 profile 指定的数据库 MCP **只读 SELECT** 旁证（只读走查里是辅助、非必需；写路径联调里是每态必做）。
7. **出报告**：见 §3。

## 2. 通用硬规则（可移植，务必遵守）

- `take_snapshot` / 断言前**必先 `wait_for`** 一个目标页才会出现的新文本，别靠固定 sleep。
- 切角色后**先 wait 再验证**当前角色，别立刻读旧页面。
- **查库看真值，不看前端 toast**：toast 只是提示，落库对不对以 SELECT 为准。
- **bug 即时记录**：发现即写进 bug 清单（现象+可定位信息），别攒到最后忘了。
- **卡住即收敛**：同一操作连续 2 次无进展（超时/找不到元素/弹窗拦截）→ 记「受阻：<现象>」跳过，继续下一项。绝不空转、不输出半截工具调用。
- 接近 profile 的步数预算就收敛、立即出报告。

## 3. 报告 / bug 结构骨架（占位符化）

最后一条消息必须是**完整的结构化中文报告正文**，末尾不得残留工具调用；中途受阻/预算耗尽也要出**部分报告**（写清哪些走了、哪些没走到及原因）。若 profile 指定了报告落盘路径，用 `Write` 落盘后再在返回文本里给出正文。
