# 资讯模块升级：AI 摘要 + 标签 + 语义检索（Zilliz Cloud）

## Context（为什么做）

「资讯」模块随信息源增多（AI 日报 / 每日新闻 / Hacker News / GitHub Trending / Product Hunt / 少数派）数据变多，但：
- 每条只有 `{title, summary, url, source}`，**无标签、无分类**；且 `summary` 质量参差——HN 的"摘要"只是"▲分数·作者·评论数"元信息、每日新闻 summary 恒空。用户**必须逐条点进原文才知道讲什么**。
- 资讯模块**没有任何搜索/过滤/标签 UI**，无法快速检索匹配感兴趣内容；知识库搜索是纯子串匹配、无语义。

**目标**：刷新时对每条自动生成 **统一质量的一句话摘要 + 标签**，并写入 **Zilliz Cloud 向量库** 支持 **语义检索**；前端加 关键词/标签/来源筛选（客户端离线）+ 语义搜索框（后端+Zilliz），让用户不点原文即知内容、并能按兴趣语义匹配。

## 锁定决策（来自与用户对齐）

| 项 | 决策 |
|---|---|
| 能力档位 | 重·语义向量检索，用用户的 **Zilliz Cloud serverless**（REST API v2） |
| embedding 来源 | **自算 BYO**：后端 `urlopen` 调 OpenAI 兼容 embedding 端点；key 在 `workbench.local.json`；**collection 维度建库时探测自动定** |
| 连接方式 | **REST + 标准库 urlopen**，不装 pymilvus（贴合"依赖极简且可撤回"北极星 / ADR 0010） |
| collection | 未建，**由本方案设计 schema 并给建库脚本**（幂等） |
| 附带 | 同时产出 摘要+标签+向量；前端 关键词/标签/来源筛选=客户端离线，语义搜索=后端 |

## 架构与数据流

```
fetch_*.py(抓取, 不变)
   → 【新】backend/pipeline/enrich.py  （对每条: 摘要+标签 via chat; 向量 via embedding; 按 url 缓存跳过已处理）
        ├─ 回写 aiSummary/aiTags 进各源 *.json（供 export 透传）
        └─ 向量 upsert 进 Zilliz（backend/clients/zilliz.py）
   → export_data.py（聚合写 data.json, 透传新字段, 14 天 history 不变）

前端 js/views/info.js:
   关键词框 + 标签 chip + 来源 chip  →  纯客户端过滤 data.json(离线即时)
   语义搜索框  →  POST /api/info/search  →  后端 embed(查询) → Zilliz search → 返回排序 → 复用 renderNewsItem 卡片
```

## 图先行（第一性原理 + 流程/时序图，开工产物）

**第一性拆解**：人的注意力线性稀缺；诉求正交为两个基本需求——①"不点进去就知道讲啥"=信息压缩（每条一句话摘要+标签，一次算好缓存）；②"快速找到我关心的"=匹配，再分**词面匹配**（比对字符：关键词/标签/来源，便宜·离线·瞬时，但你的词≠文章的词时抓瞎）与**语义匹配**（比对意思：先把文本 embedding 成向量空间的点，"意思近=距离近"，"找相似"=最近邻搜索=Zilliz 的本职）。本质：摘要=压缩、标签=离散索引、向量=连续语义坐标，三者都是"预先提取信息换事后低成本检索"。

**据此推出三层管线，每层一条理由**：采集层只搬原文（职责单一，不动）；理解层 `enrich` 把贵/慢/不确定的智能集中发生一次，**按 url 去重缓存**让每轮成本 ∝ 新增数而非总数（幂等原理，兼护 AI 字段不被 export 覆盖），摘要+标签+向量同源一次算完；消费层两条读路径对应两种需求——浏览/筛选走客户端（不联网·瞬时），语义搜索走后端（Zilliz token 是密钥，绝不进浏览器=安全边界）。**两个不变量**：查询与文档必须同一 embedding 模型（对称性，否则距离无意义）；LLM/Zilliz 挂了资讯仍可看（可降级，回退旧 summary/关键词筛选）。

流程图与两张时序图（enrich 写双存储 / 语义搜索）已用 mermaid 渲染验证通过（`localhost:3737/flow`、`/seq_enrich`、`/seq_search`）。落码前作为契约缝依据；收尾按 `功能图解复盘-指南.md` 出三图复盘。

## 后端改动

1. **`backend/core/config.py`**：新增 `embedding()` 与 `zilliz()` 两个配置读取器（仿现有 `supabase()`/`kb()`/`chat_allow_hosts()` 范式），从 `workbench.local.json` 读：
   - `embedding: { baseUrl, model, key, dim?(可空,探测填充) }`
   - `zilliz: { endpoint, token, collection }`

2. **`backend/clients/zilliz.py`（新）**：纯标准库 `urllib.request` REST 客户端，方法 `ensure_collection(dim)` / `upsert(rows)` / `search(vector, topk, filter)` / `delete(ids)`。用 Zilliz REST v2（`${endpoint}/v2/vectordb/...`），`Authorization: Bearer <token>`。参照现有 `backend/server.py:82-92` 的 urlopen POST 构造 + `backend/clients/supabase.py` 范式。

3. **`backend/clients/embedding.py`（新，或并入 zilliz 客户端旁）**：`embed(texts:list)->list[vector]`，OpenAI 兼容 `POST {baseUrl}/embeddings`，标准库 urlopen；`probe_dim()` 用一条测试文本探测维度。

4. **`backend/pipeline/build_zilliz_collection.py`（新，一次性/幂等）**：`probe_dim()` → `ensure_collection(dim, metric=COSINE)`。schema：主键 `id`(varchar=hash(url))、`vector`(float, dim=auto)、标量 `url/title/summary/tags/source/date`（供过滤与回显；tags 存 JSON 字符串或 array 字段）。可开动态字段兜底。

5. **`backend/pipeline/enrich.py`（新）**：读各源 `*.json`；`id = sha1(url or title+source)`；
   - **幂等缓存**：读上轮 `data.json` + sidecar `enrich_cache.json`，按 `id` 建索引；已含 `aiSummary` 则跳过 LLM/embedding（照抄 `export_data.py:427-439` 的"读回上轮 data.json 合并"范式）。
   - 新条目：**批量**调 chat（`POST {baseUrl}/chat/completions`）返回 `[{id, summary(中文一句话), tags[]}]`（提示词给一份类目引导：模型/开源/产品/安全/硬件/资讯…，避免标签发散，但允许开放标签）；调 embedding 得向量。
   - 回写 `aiSummary`/`aiTags` 进源 `*.json`；`zilliz.upsert` 向量+标量；更新 `enrich_cache.json`。
   - **成本上限**：每轮 LLM 调用条数硬上限（如 200），超限记 log 并停（不无界）；**enrich 失败非致命**——保留旧摘要、不阻断 export（沿用现有各 fetch 步骤语义）。

6. **`backend/pipeline/local_refresh.py`**：`STEPS`（:25-33）在 `export_data` 之前插一步 `("AI 摘要标签向量", "enrich")`。

7. **`backend/server.py`**：新增路由 `POST /api/info/search` → `_post_info_search`：`embed(q)` → `zilliz.search` → 返回 `[{url,title,summary,tags,source,date,score}]`。**Zilliz token 只在后端**。

## 验证（端到端）

1. **建库**：`python -m backend.pipeline.build_zilliz_collection` → 探测维度、创建 collection 成功（幂等重跑不报错）。
2. **enrich 单跑**：`python -m backend.pipeline.enrich` → 各源 `*.json` 出现 `aiSummary`/`aiTags`；`enrich_cache.json` 生成；Zilliz 控制台/REST count 增长；二次跑**命中缓存、LLM 调用数≈0**（验证幂等省钱）。
3. **全链路**：重启后端 `python -m backend.server 8899`（`-m` 包方式），点「同步数据」→ `local_refresh.log` 出现 enrich 步骤 + `local refresh end (ok=True)`；`data.json` 各源 item 带新字段。
4. **chrome-devtools MCP 走查**（已开 pageId=1，勿 new_page，`evaluate_script(waitForStableDom:false)` 驱动）：
   - 资讯卡片显示 AI 摘要 + 标签 chip；点标签/来源 chip 即时过滤；关键词框离线过滤生效。
   - 语义搜索框输入 → `list_network_requests` 见 `POST /api/info/search` → 200；结果按相关度排序、卡片正常；`list_console_messages(error)` 无报错。
5. **成本/边界**：确认每轮 enrich 只对新条目调 LLM；构造超上限场景验证 fail-to-log 不死循环。
