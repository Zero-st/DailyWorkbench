# Plan · 沉淀「AI 时代程序员成长心法」到 docs/principles/

## Context

用户问：「AI coding 时代，程序员如何提升自己能力、思维」。这不是改代码的需求，是一次方法论提问。
但本仓已有一套「心法层」文档体系（`docs/principles/开发心法-多维思维总纲.md`，讲「何时戴哪顶帽子」），
而且这个仓库本身就是最好的证据：8 天 62 个 commit、约 15k 行、一人 + Claude 完成。**代码大半是 AI 写的，
真正由人产出且让项目没腐烂的，是宪章 / ADR / 心法 / 防腐方案 / skill 这些「判断与约束」。**

所以建议把这次回答按仓内既有风格（真实项目证据 + 可套用判据 + 护栏，不写空话）沉淀成一篇 principles 文档，
与《开发心法》并列：《开发心法》管「何时戴哪顶帽子」，新文管「AI 协作时代，人该长哪些肌肉、怎么练」。

## 交付物

### 1. 新建 `docs/principles/AI时代程序员成长-心法.md`

按 `docs/README.md` §2 后缀词表，`-心法` → `principles/`。结构对齐《开发心法》（性质/定位/关联头 → 编号章节 → 与其他文档分工 → 变更记录）。

内容骨架（各节都要挂本仓真实证据，禁抽象口号）：

- **§0 为什么要这份**：本仓 8 天 62 commit 的事实；反问「哪些是人不可替代的产出」→ 答案全在 docs/ 而不在 js/。
  引出核心命题：**AI 时代程序员的复利不再是代码行数，而是沉淀下来的判断力、约束和验证能力。**
- **§1 重新定价表**：贬值 vs 升值。
  - 贬值：语法/API 记忆、样板代码、「把清晰需求翻成代码」的速度、单一框架的熟练度。
  - 升值：问题定义（把模糊想法说成可验证规格）、约束设计（北极星/红线/说不）、验证能力（怎么知道它真对）、
    决策与留证（单向门/ADR）、原理级知识（用来评审 AI 的方案）、品味（什么是好的）、跨层宽度。
  - 证据：`TECH_CHARTER` 四问、`adr/0001-0005`、`.claude/plan/anti-rot-governance.md`（人发现三端漂移，AI 没有）。
- **§2 四个杠杆（能力模型）**：从「写代码的人」到「让正确的代码被写出来的人」。
  | 杠杆 | 一句话 | 本仓载体 | 练法 |
  | 规格 Specify | 写不出完成判据 = 还没想清楚 | speckit 流程 / plan 先行 | 每个任务先写一句「怎么算做完」 |
  | 约束 Constrain | AI 什么都能做，人的价值是说不 | 宪章北极星、四问、CLAUDE.md | 每引入 X 走四问 |
  | 验证 Verify | 不会验证的东西不要让 AI 造 | 真门禁 CI（禁 `\|\| true`）、chrome-devtools 走查 | 验证先于生成 |
  | 判断 Judge | 可逆性 + 维护税 + 删除测试 | 双向门/单向门、心法 §4 三关 | 每周复盘一条进宪章/ADR |
- **§3 五个思维转变（具体到操作）**：
  1. 「我怎么实现」→「我怎么知道它对」（验证优先）。
  2. 「学工具」→「学原理」：框架会被 AI 抹平，DDD/DDIA/PoEAA 这类原理才能评审 AI 方案（`design-principles` skill 就是这个用法）。
  3. 「做完」→「留证」：AI 代码没有「为什么」，为什么只在人脑里 → ADR / 宪章 / 心法。
  4. 「一次性对话」→「可复用资产」：skill / memory / prompt 库（`harvest-prompts`、`~/.claude/skills/`）。
  5. 「独行侠」→「带一个知识面无限宽但没有责任感的搭档」：委派、审查、划边界，不 micromanage 也不放任。
- **§4 AI 放大的五个坑 + 护栏**（对应《开发心法》§5，AI 让它们更危险）：
  | 坑 | 为什么被 AI 放大 | 护栏 |
  | 产品帽更被挤掉 | 造得越快越容易造没人用的东西（`cap/ov/sess/schedule` 整批删） | 心法 §4 三关，AI 时代必须先过 |
  | 理解债 | 没读懂也能跑 → 出事修不了 | 「一文件一句话说清」；读不懂的不合并 |
  | 技能萎缩 | 判断力来自实践，从不动手判断会退化 | 每周一次无 AI 手写核心逻辑；把 review AI 输出当练习 |
  | 验证幻觉 | 「测试通过」≠ 通过（假绿 CI 就是化身） | 真门禁，亲眼看红变绿 |
  | 重构爽感放大 | AI 让重构近乎免费 → 更容易逃避方向决策 | 心法 §5 护栏：动手前写「这次解决谁的什么问题」 |
- **§5 练习节律**（按频率分层，像心法 §4 一样可量化）：
  - 每任务：一句完成判据 + 戴哪顶帽子。
  - 每产出：读懂再合并；问「为什么这么做」；找一处能删的。
  - 每周：一次无 AI 手写；一条经验进宪章/ADR/skill。
  - 每月：原理书一章 + 在项目里找一处对照应用。
  - 长期：横向跨一层（前端→后端/数据/运维），因为 AI 把跨层沟通成本打下来了，宽度成杠杆。
- **§6 与宪章 / 开发心法 / ADR 的分工**：本文 = 「人该长哪些肌肉」；开发心法 = 「何时戴哪顶帽子」；
  宪章维度四 = 「人机协作的操作红线」；ADR = 留证。不重复。
- **§7 变更记录**：2026-09-03 v1.0 初版 + 缘起一句。
