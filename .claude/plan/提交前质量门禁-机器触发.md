# 提交前质量门禁：从「靠人记」升级为「机器触发」

## Context

**起因**：用户提议「每次提交前检查代码质量 → 总结坑点 → 整理为规则文档 → 下次 commit 前先扫规则再审查」，并问有没有更好方案。

**查证结论：这个方案本仓已经有了，而且比提议版本更成熟。**
- `docs/开发测试规范.md` §3 = 已知坑点台账（跨维度 7 条 + 取数管线 6 条），是全仓唯一真源
- §3.0 = 三档升级判据（📄 文档 → 🤖 门禁 → 🏗 设计），**同一坑复发第 2 次即判定文档失效，当场升级**
- §3.0 反向判据 = **拦不住任何真实事故的门禁是废话，该删**（防门禁通胀）
- 提议版本缺的正是这两个「出口」——只谈规则怎么进来，没谈怎么升级、怎么出去

**所以真正的缺口只有两个：**

1. **触发点无强制力。** `.git/hooks` 为空、无 `core.hooksPath`、无 Claude Code hooks、无 `.pre-commit-config.yaml`。五项门禁（`bump_version.py --check`、`check_design_tokens.py`、`check_docs.py --check`、flake8、pytest + 独立 job 的 `tsc`）**只在 push 之后的 CI 跑**。「提交前扫一遍」今天 100% 靠人记 —— 按 §3.0 自己的判据，这就是 📄 档，已被本仓实证会失效。

2. **台账无封顶机制。** 条目只进不出：升上 🤖 门禁之后，正文照样占篇幅。13 条还读得完，膨胀后「扫描规则文档」必然退化成走过场 —— 即宪章禁止的 `|| true` 假绿的人肉版。

**缺口 1 已有现成实证**：`docs/版本管理规范.md` §4 的「提交前手跑清单」只列了 `bump_version.py --check` + pytest，**漏了 `check_design_tokens.py` 和 `check_docs.py`**，与 `.github/workflows/ci.yml` 的五步已经漂移 —— 这正是台账里「活文档漂移」那条坑的**新实例**。本方案顺手结算它。

**预期结果**：提交前检查从「人肉纪律」变为「机器触发 + 智能跳过」，台账人读区体积封顶，且新增门禁有效性的记账输入。

## 关键设计决定（先看这段，再看改动清单）

### 决定 1 · 两类检查分两个宿主，不是双重防护

git pre-commit hook 是**同步阻塞的 shell**。把 LLM 审查塞进去 = 每次 commit 卡几十秒到几分钟、且无界面呈现 findings、无法对话修改 → 必然导致习惯性 `--no-verify` → 整套门禁全废。

| 层 | 检查内容 | 宿主 | 阻塞？ | 覆盖范围 |
|---|---|---|---|---|
| **L1** | 机器四项，<5s，零判断、零假阳性 | `.githooks/pre-commit` | **✅ 阻塞** | 所有提交（手敲 + AI） |
| **L2** | LLM 代码审查（`/code-review`） | Claude Code `PreToolUse` | **❌ 不阻塞** | 仅 AI 经手的提交 |

L2 不覆盖手敲 commit —— 但手敲时本来也没有 LLM 在场，不是缺口。

### 决定 2 · LLM 审查绝不阻塞提交

依据 §3.0 原话：「**误报会逼人加豁免，豁免最终让门禁失效，宁可门小而真**」（`check_design_tokens.py` emoji 门刻意只扫 `index.html` 就是这条的应用）。

LLM 审查**有**假阳性。阻塞式假阳性 = 逼用户绕过 = 整套失效。因此：
- **只有零假阳性的机器门禁配阻塞**（L1）
- L2 呈现 findings，**提交与否由人拍板**

### 决定 3 · 审查只注入「与 diff 相关域」的坑点，不喂整份台账

这是防注意力稀释的核心。四域映射：

| diff 路径 | 注入的坑点域 |
|---|---|
| `js/` `css/` `index.html` | §3.1 前端类（emoji 直出、外部数据未过渲染层、缓存戳） |
| `backend/` `scripts/` | §3.2 取数/管线全部 6 条 |
| `docs/` `*.md` | §3.1 活文档漂移 + `docs/文档规范.md` §4.3 写作红线 |
| `.github/` `check_*.py` | §3.1 假 CI（`\|\| true`）+ 状态字段说谎 |

### 决定 4 · 逃生门必须留且在文档里明说

`git commit --no-verify` 跳过 L1。**没有逃生门的门禁，最终会被整体拆掉**。明写在 `docs/版本管理规范.md`，并说明代价（CI 仍会红）。

### 决定 5 · 命中记账只用于排序，不自动删门禁

**零命中 ≠ 无用** —— 可能恰恰是因为它有威慑力，大家不犯了。记账的用途是给 §3.0 反向判据提供**排序输入**，人来拍板删不删，绝不做自动删除逻辑。

## 改动清单

### A · `check_all.py`（仓根，**新建**，纯标准库）

单一真源的门禁聚合器，CI 与本地 hook 都调它 —— **消灭「CI 清单 vs 手跑清单」漂移**。

**必须处理的坑：三个脚本 `--check` 语义不一致**（探查实测）：

| 脚本 | 调用方式 | 陷阱 |
|---|---|---|
| `bump_version.py` | **必须带 `--check`** | **无参会写盘**，在 hook 里误调会改工作区 |
| `check_design_tokens.py` | 带不带都行 | `--check` 是纯装饰，与无参行为相同 |
| `check_docs.py` | **必须带 `--check`** | 无参是报告模式，**恒退 0**，不带就是假绿 |

参数：
- `--check`：任一硬门违规 → 退 1（hook 与 CI 用）
- `--strict`：**外部工具缺失（pytest / flake8 / node）视为失败**。CI 用；本地缺 node 时打印 `SKIPPED: tsc (node 不可用)` 并继续。**禁止 `|| true`**，跳过必须显式打印，不得静默转绿（宪章维度三）。
- `--stats`：读 `gate-hits.local.jsonl`，按命中次数排序打印各门禁，供 §3.0 反向判据决策。

覆盖项（对齐当前 CI）：`bump_version.py --check` · `check_design_tokens.py` · `check_docs.py --check` · `flake8 --select=E9,F63,F7,F82` · `pytest -q` · `tsc --noEmit -p jsconfig.json`

失败时追加一行到 `gate-hits.local.jsonl`：`{"ts", "gate", "exit"}`。

### B · `.githooks/pre-commit`（**新建**）+ 启用

```sh
#!/bin/sh
# 逃生门：git commit --no-verify
exec "${WB_PYTHON:-python3}" check_all.py --check
```

- 入仓可审；一次性启用 `git config core.hooksPath .githooks`（**换机需重做**，写进 README 与版本管理规范）
- `WB_PYTHON` 覆盖口是为本机 anaconda 解释器（`/home/dev_st/iriswork/tools/anaconda/bin/python`）留的，hook 本身保持可移植

### C · Claude Code `PreToolUse` hook（**新建**）

- `.claude/settings.json`（**新建，入仓**）—— 现有 `.claude/settings.local.json` 只有一条 `permissions.allow`，不动它
- `.claude/hooks/precommit-review.sh`（**新建**）

逻辑：
1. 非 `git commit` 命令 → 立即放行
2. `git diff --cached --name-only` **未**命中 `^(js/|backend/|scripts/)` 且无 `\.py$` → 放行（纯文档/计划件提交跳过，对应 Q2 选择）
3. 算 `git diff --cached | sha256`，与 `.claude/.review-cache` 比对 → 已审过则放行
4. 否则 `permissionDecision: "deny"` + reason：「本次 staged diff 命中代码，请先跑 `/code-review`（限 staged 范围），并注入 `docs/开发测试规范.md` §3 中与本 diff 相关域的坑点（见决定 3 映射表）；审完把 diff sha 写入 `.claude/.review-cache` 再提交」

> 参考：`.claude/skills/git-guardrails-claude-code/SKILL.md` 第 46/66/81 行已有 `hooks.PreToolUse` 配置模板可复用，该 skill 至今未被应用到任何 settings 文件。

`.gitignore` 追加：`.claude/.review-cache`、`gate-hits.local.jsonl`

### D · `docs/开发测试规范.md` §3.1 拆两段（台账封顶）

- **§3.1 在办（📄 档 · 需人读）** —— 4 条：外部数据直出未过渲染层、假 CI、**状态字段说谎 🔴（复发 2 次，已达升级线、门禁待设计）**、硬编码环境绑定

## 不做什么

- **不新建「坑点规则文档」** —— §3.0 明写「禁止再写第 3 份文档」，全部落进既有真源
- **不做门禁自动删除逻辑** —— 见决定 5
- **不现在给「状态字段说谎」设计门禁** —— 台账已标 🔴 刻意只登记不动手，塞进本批次会变成「什么都做一点」的元工作
- **不引入 pre-commit 框架 / husky 等外部依赖** —— 宪章「零构建 · 依赖极简且可撤回」，`check_all.py` 走纯标准库

## 验证

### 1 · 红绿证据（照 fd241d3 做法，每项都要留证据进 CHANGELOG）

```sh
# 绿基线
python check_all.py --check ; echo "exit=$?"        # 期望 0

# 红：故意塞 emoji 进 index.html
python check_all.py --check ; echo "exit=$?"        # 期望 1，且指名 check_design_tokens
git checkout index.html
```

### 2 · L1 hook 真的拦得住

```sh
git config core.hooksPath .githooks
# 改一个 js/ 文件但不跑 bump_version
git add js/xxx.js && git commit -m "test"           # 期望被拦，报缓存戳不同步
git commit --no-verify -m "test"                    # 期望放行（逃生门可用）
git reset --soft HEAD~1                             # 撤回验证提交
```

### 3 · L2 CC hook 的触发与跳过

- 改 `backend/*.py` 后让我提交 → 期望被 deny 并提示先跑 `/code-review`
- 只改 `docs/*.md` 后提交 → 期望直接放行（Q2 的「有实质代码改动时」语义）
- 跑完审查写入 `.claude/.review-cache` 后重试 → 期望放行

### 4 · 门禁自身不破坏既有门禁

```sh
python check_docs.py --check       # 新增/改动文档后索引一致性仍绿
python -m pytest -q                # 89 个既有测试全绿
python check_all.py --stats        # 记账文件可读、排序输出正常
```

### 5 · 新增代码要有测试

照 `test_workbench.py` 既有做法（`tmp_path` + `monkeypatch`，零网络），为 `check_all.py` 补：`--check` 退出码语义、`--strict` 下工具缺失判红、记账行格式。**特别是守住「`check_docs.py` 必须带 `--check`」这条**，防止未来有人改成无参调用造成静默假绿 —— 参照仓里已有的 `check_docs` 解析器 fail-closed 守卫测试。
