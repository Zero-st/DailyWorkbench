# 需求澄清工具选型对比

> 版本：v1.0　制定：2026-08-31
> 定位：**"需求摇摆时，用什么跟 AI agent 边对话边把需求钉死"** 的选型账本，供离线慢慢挑。
> 性质：**reference / 调研**。热度数据是 2026-08-31 快照（会变），以各 repo 官方页为准。
> 关联：`知识飞轮-路线图.md`、`项目总览-需求与进度.md`（**这两份就是你现有的需求文档**）、`界面设计准则.md`。

---

## 0 · 一句话 + 怎么用这份文档

**你缺的多半不是工具，是把"摇摆"逼问清楚的一次结构化对话。** 按三轴挑：**轻 / 重**（学习使用成本）× **装不装外部**（供应链风险）× **信任度**。

快速路径：
- 只想**尽快把想法理顺** → 用你**已内置的 `/brainstorming`**（零装、零风险，今天就能开）。
- 想要**结构化、可长期复用的 spec** → **GitHub Spec-Kit**。
- 想要**像有个产品团队反复逼问你** → **BMAD-METHOD**（愿吃学习成本再上）。

> ⚠️ 先记住一条：你的 `知识飞轮-路线图.md` + `项目总览-需求与进度.md` **已经是需求文档**。很多时候"需求摇摆"的解法是**重开一轮对话、然后更新这两份**，而不是再装一个工具。

## 2 · 逐个工具卡

### ⭐ 内置 `/brainstorming`（首推起点）
- **是什么**：Anthropic 第一方 skill，你本会话已经用过（当时理"知识飞轮"路线）。
- **怎么做需求对话**：直接 `/brainstorming <你的模糊想法>`；它会逐点追问、帮你收敛，最后给结构化结论。
- **安装**：无需安装，已在你环境里。
- **产出物**：对话确认后的结论 → 你手动落进 `知识飞轮-路线图.md` / `项目总览`。
- **优点**：零装、零供应链风险、第一方可信、上手最快。
- **代价 / 何时不够**：不产出正式 `spec.md/tasks.md`；不强制"约束→验证"闭环。需要长期结构化归档时偏轻。

### 🏛️ GitHub Spec-Kit ★132k（结构化正式流）
- **是什么**：GitHub 官方开源"规格驱动开发"工具包，最主流。
- **怎么做需求对话**：`/speckit.specify`（把模糊想法生成详细 spec）→ **`/speckit.clarify`（分析当前 spec、逐条提问补齐缺口与歧义，按你答案回写 spec）** → `/speckit.plan` → `/speckit.tasks`。共 9 条命令（constitution/specify/clarify/plan/tasks/implement/analyze/checklist/taskstoissues）。
- **安装**：`uvx specify init`（初始化时选 Claude Code），或用其 Claude Code 插件。**精确命令以官方 README 为准**（会更新）。
- **产出物**：`constitution.md`（原则）/ `spec.md`（需求+用户故事）/ `plan.md`（技术设计）/ `tasks.md`（任务表）。
- **优点**：官方最稳、结构化强、多 agent（Claude/Cursor/Copilot）通用、`/clarify` 正中你需求。
- **代价 / 何时不该用**：引入一套外部工具链 + 一套流程要学；对"就想快速捋一下"是过重。局限：Claude 对 spec"尽量遵守但不保证严格"。
- **链接**：https://github.com/github/spec-kit ｜ [GitHub 官方 blog](https://github.blog/ai-and-ml/generative-ai/spec-driven-development-with-ai-get-started-with-a-new-open-source-toolkit/)

### 🤖 BMAD-METHOD ★52k（全能 agent 团队）
- **是什么**：不是单个 skill，是**一整套"敏捷 AI 团队"框架**——内置分析师(Analyst)、产品(PM)、架构师、SM、Dev、QA 等角色 agent。
- **怎么做需求对话**：**Analyst / PM agent 跟你反复对话**做需求挖掘、出 PRD / 用户故事，正对你"不断对话确认需求"的诉求。
- **安装**：`npx bmad-method install`（交互式安装器；**以官方 README 为准**）。
- **产出物**：需求/PRD/架构/故事等一整套文档 + 分阶段流程。
- **优点**：最贴"像有个产品团队逼问你"，覆盖从需求到实现全链路，社区很活跃。
- **代价 / 何时不该用**：**重**——角色多、概念多、学习曲线陡；对一个个人工作台小项目可能过度。想深度产品化再上。
- **链接**：https://github.com/bmad-code-org/BMAD-METHOD

### 🧩 中量替代
- **Pimzino/claude-code-spec-workflow ★3.8k**：Req→Design→Tasks 自动化工作流。注意**近一年（2025-09 后）没更新**，上前确认是否维护。https://github.com/Pimzino/claude-code-spec-workflow
- **PRD 类 skill**（[rsmdt/product-requirements](https://www.skillsdirectory.com/skills/rsmdt-product-requirements)、[prd by 48nauts](https://claudeskills.club/skills/prd-by-48nauts-operator)）：交互式提问帮你把模糊功能变成结构化 PRD（用户故事/验收标准）。轻，但属社区 skill，装前读源码。

## 3 · 决策指引（给纠结的人）

| 你的处境 | 选它 | 理由 |
|---|---|---|
| 就想**尽快把摇摆想清楚**，不想装东西 | **内置 `/brainstorming`** | 0 成本、0 风险、今天就能开；先做 |
| 想要**结构化 spec、长期复用、正式化** | **GitHub Spec-Kit** | 官方最稳，`/clarify` 专治歧义 |
| 想要**产品团队式反复逼问需求 / 出 PRD** | **BMAD-METHOD** | 分析师/PM agent 深挖；但愿吃学习成本再上 |
| 只想要**一份 PRD**、不要整套流程 | PRD 类 skill | 轻量、交互问答；注意社区来源 |

**务实提醒**：动新工具前，先问一句——"我这次是**真需要新工具**，还是**重开一轮 `/brainstorming` + 更新路线图/总览**就够了？"（对照 `design-principles` 卡 4「一上来就想引入中间件」＝YAGNI）。

## 4 · 安全红线（装社区 skill 前必看）

- Snyk「ToxicSkills」审计：**36% 的社区 skill 至少有一个安全缺陷、13.4% 有严重问题、76 个已确认恶意载荷**。
