## 0 · 为什么要这份（一个真实翻车）

「多读书多思考就能提高产品思维」是句正确的废话。先看本仓一个真实教训：`cap / ov / sess / schedule` 四个视图，造出来才发现没人用，一次 commit（`c7b14ad`）整批删掉，删时**一点不心疼**（见 [`AI时代…心法`](AI时代程序员成长-心法.md) §5、[`开发心法`](开发心法-多维思维总纲.md) §1）。删得不心疼，恰恰说明当初就是产品判断失误——**不是不会写，是不该造**。

问题来了：判断力怎么练？[`开发心法`](开发心法-多维思维总纲.md) §4 给了一套判据（三门 / 维护税 / 四档 / 删除测试），但判据是**尺子**，会量不等于量得准。量得准，靠的是**见过足够多的样本**。而你一个人的项目，一年也造不出几个功能，反馈以周计——**光靠自己的项目，练一辈子也见不到几个真实案例。**

**所以本文补的是姊妹篇缺的那一环：向外取样。** 把每天本来就在刷的 GitHub / X / 小红书 / 产品经理帖子，变成低成本的判断力训练集——别人替你把产品造出来、把市场验证过了，你只出「拆解」这一份力。

## 1 · 产品思维在判断什么（五根轴 · 各挂一个真实出处）

「产品思维」太大，练不了。把它拆成五根**可迁移的判断轴**，每根配一句「拿到任何产品/帖子都能问的话」，再挂一个**真实出处**（出处均可核实，见文末 §附）：

| 判断轴 | 拿到任何东西都能问的一句 | 真实出处（可核实） |
|---|---|---|
| **用户价值** | 它把什么旧体验换成了什么新体验？替换成本值不值？ | 俞军《俞军产品方法论》：用户价值 ＝（新体验 − 旧体验）− 替换成本 |
| **需求真伪** | 是真痛点，还是「我以为用户要」？ | 梁宁《产品思维30讲》痛点/痒点/爽点；Marty Cagan「客户不是创新的源头」 |
| **取舍/优先级** | 哪些是高杠杆的少数，哪些是占满时间却不出活的杂务？ | Shreyas Doshi 的 LNO 框架（Leverage / Neutral / Overhead） |
| **定位/信息设计** | 一句话能不能让「谁」秒懂「它替代了谁」？ | Supabase 把定位改写成「开源版 Firebase」 |
| **分发/上手摩擦** | 用户从看到到用上，卡在哪一步？ | shadcn/ui 用「复制粘贴代码」绕开安装依赖 |

**读法**：这五根轴不是背的，是**问的**。下面 §3 每个平台，都是拿这五句去拆别人的现成答案——拆得越多，尺子越准。

## 2 · 为什么必须「从别人的产品里学」

[`开发心法`](开发心法-多维思维总纲.md) §3 讲过一个不对称：工程帽有即时反馈（代码跑通＝爽），产品帽反馈滞后几周（「这功能我真在用吗」要用一阵才知道）。这个滞后对**自建项目**是致命的——你造一个功能要几天，验证要几周，一年下来能亲历的产品判断不过十几次。

破法只有一个：**用别人的产品当训练集**。GitHub 上一个 star 暴涨的仓库、X 上一条被反复转发的框架、小红书一条十万赞的笔记——都是**已经过市场验证**的样本，成败摆在那里，你不用自己造、不用等几周，直接拆。

一条必须挂门口的警告——**幸存者偏差**：你刷到的几乎全是活下来的爆款。只拆成功案例，会学成「所有定位改写都会成」。**要刻意去看死掉的**：Product Hunt / HN 上无人问津的同类、GitHub 上被归档（archived）的仓库、你自己删掉的那四个视图。失败样本往往比成功样本信息量更大。

## 3 · 平台采矿手册（拿五根轴去拆真实案例）

每个平台一节：**淘什么 / 怎么拆一条 / 真实案例卡**。案例全部可核实（§附）。

### 3.1 GitHub —— 仓库就是产品，README 就是落地页

- **淘什么**：定位一句话、README 的信息设计、上手摩擦（DX）、分发方式。star 曲线陡增那一段，往往对应一次产品判断。
- **怎么拆一条**：打开任一爆款 repo，套「用户价值」轴——它把什么旧体验（旧工具）换成了什么新体验？替换成本（迁移、学习）是多少？
- **真实案例卡**：
  - **Supabase（定位即产品工作）**：最早自我介绍是「realtime Postgres」，没人听得懂；在 YC 期间改成一句「**开源版 Firebase**」，2020 年春连上两天 Hacker News 头条。产品没大变，**换了一句让人秒懂「它替代了谁」的话**——这就是「定位/信息设计」轴。
  - **shadcn/ui（分发即产品工作）**：反常识地**不做成 npm 库**，而是让你把组件源码「复制粘贴」进自己项目。牺牲「一键升级」，换来「代码归你、随便改、无黑盒依赖」——一个精准取舍，戳中开发者「不想被库绑架」的真痛点。
  - **Cal.com（需求发现）**：创始人当初到处搜「Calendly open source」，搜不到，**于是自己造**——「找不到＝未被满足的需求」是最朴素的需求发现，后来 Product Hunt 当日第一。
  - **Plausible（减法定位）**：不跟 Google Analytics 拼功能，反着来——隐私优先、无 cookie、脚本约 1KB，一句「**GA 对多数站点是杀鸡用牛刀**」。**做减法**也是一种定位。

### 3.2 X / 英文产品博主 —— 淘的是「框架」和「反直觉取舍」

- **淘什么**：能迁移的思考框架、别人踩过的坑、反直觉的取舍。**别淘金句**（见 §5）。
- **怎么拆一条**：看到一个框架先问两句——「它在**我这个**处境能落地吗？」「它的**反例**是什么？」都答上，才算学到。
- **真实案例卡**：
  - **Shreyas Doshi（取舍轴）**：LNO 框架把任务分成 Leverage（高杠杆）/ Neutral / Overhead（占时不出活），主张把精力压在 Leverage（[原推](https://x.com/shreyas/status/1399061782560350208)）。他另一句更狠：「**多数执行问题，其实是战略问题**」——执行再拼，方向错了都是 Overhead。
  - **Marty Cagan / SVPG（需求真伪轴）**：区分 empowered team（被授权去发现解法）与 feature team（只照单交付功能）；强调**产品发现**先于交付，且「客户不是创新的源头」——用户能说出痛，说不出解法。
  - **Julie Zhuo（优先级 + 直觉校准）**：Facebook 前设计 VP，《The Making of a Manager》作者。她那篇「**Prioritize until it hurts**」（排优先级要排到「砍掉也心疼」才算真排过）直接呼应 §0 的删除测试；她也常谈产品直觉怎么用「**直觉 vs 数据**」两条腿校准。（她的博客 The Looking Glass 正是 Lenny's Newsletter 的启蒙。）
  - **Lenny Rachitsky（体系化）**：前 Airbnb，Lenny's Newsletter 120 万+ 订阅，把大量隐性经验做成可套用框架（增长的 racecar 模型、W 型增长规划）。适合当「框架索引」——但记住本节拆法，**别只收藏**。

### 3.3 中文经典 / 博主（知乎 · 得到 · 公众号 · woshipm）—— 淘的是「体系」和「入门骨架」

- **淘什么**：成体系的方法论、可套用的公式、入门骨架。中文内容强在系统，弱在常是二手转述——**尽量回溯到原作者**。
- **真实案例卡**：
  - **俞军（公式）**：用户价值 ＝（新体验 − 旧体验）− 替换成本。一个能**当场套用**的判断轴，§1 的锚。
  - **梁宁《产品思维30讲》（同理心）**：痛点 / 痒点 / 爽点、「满足与不爽」——把「需求真伪」轴讲得能上手。
  - **苏杰《人人都是产品经理》（入门骨架）**：2010 年那本，自陈「为 -1 到 3 岁的产品经理而作」，搭了用户/需求/项目/团队/战略的骨架；同名社区 woshipm.com 是中文产品内容大本营（也含大量二手转述，按上面「回溯原作者」用）。
  - **刘飞《从点子到产品》《产品思维》**：前滴滴 / 点我达产品负责人、知乎「产品经理」话题优秀回答者，主线是「深度理解用户、实现用户价值、持续迭代」。

### 3.4 小红书 —— 诚实说：这里最难核实，所以换个用法

小红书上确有产品经理博主，但**具体某条笔记的原文我无法逐条核实**——所以本文**不编造「某博主说过……」**。它有两种**可核实**的正经用法：

1. **把小红书本身当拆解对象**。它是月活数亿的产品，公开的深度拆解很多：优设《月活2亿的小红书产品设计万字拆解》、人人都是产品经理的多篇小红书产品体验报告。拿 §1 五根轴去读这些拆解，比读任何「涨粉技巧」都值。
2. **每条爆款笔记＝一个微型产品漏斗**。选题＝需求（为谁解决什么）、标题＝钩子（留存）、封面＝转化（点击）。刷到一条高赞笔记，别只看内容，拆它的漏斗：它精准服务了谁的什么需求？这是「需求真伪 + 转化」轴的免费练习场。woshipm《拆解小红书100个博主》就是这种「逆向拆解找规律」的范本。

**读法**：平台越难核实，越要靠**可验证的公开拆解 + 自己的一手观察**，而不是转发「某大佬说」。这条对所有平台都成立，小红书只是把它逼到了台面上。

## 4 · 把「刷」变成「练」：一条通用拆解流程

光看不拆＝消遣。给任何一条帖子 / 一个仓库套下面这条流水线，五分钟，就把消遣变成刻意练习：

```
刷到一条内容 / 一个爆款 repo
   ↓
①它服务谁的什么需求？        （需求真伪轴：说不清「为谁」→ 多半是金句，划走）
   ↓
②新体验 − 旧体验 − 替换成本？  （用户价值轴：套俞军公式，正得多明显？）
   ↓
③它做了什么取舍/定位？        （取舍 + 定位轴：为得到 A，放弃了什么 B？）
   ↓
④在我的处境能落地吗？反例？    （可证伪：想一个它会失效的场景，想不出＝没真懂）
   ↓
⑤沉淀一句话 → 进知识库        （接飞轮：一句你自己的判断，不是原文摘抄）
```

**铁律：终点是「一句你自己的判断」，不是一条收藏。** 过不了第①和第④步的内容，直接划走——那是消费，不是学习。这条流程与 [`开发心法`](开发心法-多维思维总纲.md) §2「每一步只戴一顶帽子」同构：拆解时只戴产品帽，别中途跳去想「这个用什么技术栈实现」。

## 5 · 淘内容的四个坑 + 护栏

| 坑 | 护栏 |
|---|---|
| **收藏＝学会的幻觉**：存了 200 条帖子，一条没拆 | 只有过了 §4 五步、写出「一句自己的判断」的，才算学过；收藏夹不算资产 |
| **追热点框架不落地**：见框架就记，从不问「我这儿能用吗」 | 每个框架强制配「本处境能否落地 + 反例」，答不出就不算收 |
| **精致鸡汤 + 幸存者偏差**：金句爽、成功案例多、失败被隐藏 | 划走无「为谁解决什么」的金句（§4 第①步）；每看 N 个爆款，刻意找 1 个死掉的同类 |
| **只抄结论不抄推导**：记住「要做减法」，却不知 Plausible 为什么敢减 | 拆的是**推导链**（它面对谁、放弃了什么、换到了什么），不是结论一句 |

**规律**：四条护栏没有一条是「更自律地多看」，全是**把「看」改成「拆」的动作**。护栏 > 自律——这条和两篇姊妹篇一字不差。
