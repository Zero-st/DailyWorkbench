## 0 · 为什么要这份（一人项目的真实失败模式）

抽象讲「要有产品/设计/工程思维」没用。真相是：**你不缺任何一种思维**——四种你都在做，都沉淀成了文档（见 §1 的映射）。一人项目真正的失败模式只有两条：

1. **戴错帽子的时机**：功能还没验证「对我真有用吗」，就先用工程思维打磨到镀金；界面还没确认会不会天天用，就先像素级抠设计。
2. **舒服的帽子挤掉难受的帽子**：工程/重构最爽（可控、有即时成就感），产品判断最难受（要诚实问「这东西我自己会用吗」）。于是不知不觉一直在重构，回避方向决策。

**所以这份心法不是教你新框架，是给你两样东西**：① 戴帽子的**顺序感**（§2）；② 一条防「舒服帽挤掉难受帽」的护栏（§5）。外加对一人项目最该加权的**产品帽**给一套可套用判据（§4）。

## 1 · 四顶帽子 · 各一句必问 · 缺了它长什么疮

每顶帽子对应一个必问的问题，缺了它会长出的疮，本项目**全都真实发生过**：

| 帽子 | 必问一句话 | 缺了它长的疮（本项目真实证据） | 已有载体 |
|---|---|---|---|
| **产品** | 「这功能我**这周**会用它几次？为谁？」 | `cap/ov/sess/schedule` 四个视图——造了才发现没人用，**已整批删**（[`ADR 0005`](../adr/0005-pc-first-drop-native-mobile.md) 周边收敛）。删时一点不心疼 = 当初就是产品判断失误。 | [路线图](../planning/知识飞轮-路线图.md)、[IA评审](../design/产品-IA评审.md)、[项目总览](../planning/项目总览-需求与进度.md)、[走查评审](../design/工作台走查评审-v0.8.0.md) |
| **设计** | 「陌生人第一眼看，会不会觉得『坏掉了』？」 | emoji 图标豆腐块 □（走查 U1，已修）。功能全对，但「皮」没做 → 第一印象崩。 | [界面设计准则](../design/界面设计准则.md) |
| **工程** | 「三年后 / 换台机，这还跑得起来吗？」 | 2139 行单 IIFE、硬编码 `E:\` 路径、假 CI（`\|\| true` 恒绿）——见宪章末尾回溯表。 | [TECH_CHARTER](../TECH_CHARTER.md) + CI 硬门禁 |
| **决策** | 「这扇门走错了，能退回来吗？」 | 可逆小事反复纠结；不可逆的事却不留证。 | 双向门直接试 / 单向门写 [ADR](../adr/) |

**读法**：缺产品帽 → 造没人用的东西；缺设计帽 → 功能对但看着坏掉；缺工程帽 → 换机即废；缺决策帽 → 该慢的地方快了、该快的地方慢了。

## 2 · 帽子不是并行戴，是**排队戴**

一人项目最典型的病：**想法阶段就跳到工程帽**（写代码最爽、最可控），跳过了最难受的产品判断。正确的排队：

```
想法  →【产品帽】这周用几次？为谁？   答不上来 → 直接砍，别造
 ↓
验证  → 最小闭环手动跑一遍            （蒸馏库就是范本：先跑通最窄闭环，再谈优化）
 ↓
设计  →【设计帽】能复用现成组件就别新造类（界面准则 §6 检查清单）
 ↓
实现  →【工程帽】YAGNI + 双向门先试 + 模块边界（一文件一句话说清）
 ↓
验收  → 走查：chrome-devtools，console 零 error，明暗两主题各看一遍
 ↓
复盘  →【决策帽】这轮哪条经验值得写进宪章 / 该不该留 ADR
```

**铁律：每一步只戴一顶帽子。** 在「想法」阶段纠结用 SVG 还是字体栈（工程细节）= 戴错帽子；在「实现」阶段还在问「这功能到底要不要」= 该戴产品帽时没戴。

## 3 · 一人项目必须刻意给「产品帽」加权

大厂里产品/设计/工程是三拨人，天然制衡。你一个人，**必须刻意给产品帽加权**，因为反馈周期不对称：

- **工程帽有即时反馈**（代码跑通=爽）→ 会自我强化 → 天然过重；
- **产品帽反馈滞后几周**（「这功能我真在用吗」要用一阵才知道）→ 天然被拖延 → 天然过轻。

所以对你，「要有多种思维」的**真正操作含义**是：**别让工程思维的爽感，替你做了本该产品思维做的决定。** [知识飞轮-路线图](../planning/知识飞轮-路线图.md) 是产品帽的锚——动手前回去看一眼：这件事是在让飞轮转得更快，还是只是在擦飞轮的漆？

## 4 · 产品帽判据 · 怎么判断一个功能值不值得造（核心 · 可套用）

### 第 1 关 · 入场券（三个硬门，任一为否 → 直接砍，不进打分）
1. **频率门**：写下具体数字——「这周我会用它几次？」`< 2 次/周` → 砍，或降级成手动做。（YAGNI 的可量化版）
2. **飞轮门**：它让飞轮哪个环节转得更快？`输入→捕获→沉淀→蒸馏→复用`。**指不到任何一环 → 你在擦漆，不是转轮。**
3. **人在环中门**（价值观红线）：它**帮我思考**还是**替我思考**？替我思考（如后端全自动蒸馏）→ 撞取舍，慎。

### 第 2 关 · 值不值得（性价比 + 维护税）
> **收益 = 频率 × 每次省的摩擦 × 对飞轮的杠杆**
> **成本 = 造的工时 +「维护税 × 3 年」**

一人项目最容易漏**维护税**：每个功能都是未来每次改动要绕过、每次走查要覆盖的长期负担。判据：**收益要能覆盖「维护税×3 年」**。覆不住 → 砍，或用一次性脚本代替（放 scratchpad，别进产品）。

### 第 3 关 · 造到什么程度（四档投入，别二元）
| 档 | 形态 | 何时升到下一档 |
|---|---|---|
| 1 · 手动 | 纯手工做几次，不写码 | 被证明真高频、手动烦了 |
| 2 · 脚本 | scratchpad 一次性脚本 | 每天都要跑 |
| 3 · 进产品但最小 | 复用现成组件，一个按钮/视图 | 留下来了、天天用 |
| 4 · 打磨 | 抠设计/性能（如 emoji→SVG） | 只有第 3 档活下来的才配 |

**铁律：默认从第 1 档起步，被真实使用「拉」着升级，绝不跳档。**

### 第 4 关 · 反向验证 ·「删除测试」
想象它已存在，现在要删它——**你会不会心疼？** 不心疼 → 本来就不该造。用来事后校准前三关的判断力。

### 示范 · 拿路线图两个真实候选走一遍
- **捕获→卡「一步化」（后端直跑蒸馏）**：频率✅ 飞轮✅ **人在环中❌（替我思考）** + 宪章 P3 已标「较大门」 → **推迟**，真高频到烦了再评估。
- **复用端「相关时浮现」（按 topic/tag）**：频率✅（每天复盘看温故卡）飞轮✅（补强最弱的「复用」环）人在环中✅（帮你想起，不替你决定）→ **值得，从第 3 档最小做起**（先按 tag 精确匹配，别一上来搞语义相似度那种第 4 档的事）。

**规律**：同在路线图上，一个该推迟一个该做，差别不在「想不想」，在**过没过那三道门**。

## 5 · 一人项目三个坑 + 护栏

| 坑 | 护栏 | 状态 |
|---|---|---|
| 镀金 / gold-plating | 北极星 + YAGNI 四问（宪章维度一） | ✅ 已有 |
| 过早抽象 / 优化 | 双向门先试（宪章维度一） | ✅ 已有 |
| **产品帽逃避**（一直重构不发布） | **动手前一句话写下：「这次戴哪顶帽子、解决谁的什么问题」** | ⬅ 本文补 |

第三条是唯一真正缺的护栏——写不出「解决谁的什么问题」，你多半在用「打磨」逃避「该造什么新价值」，该停下来先戴产品帽。它和宪章「命令前中文说明副作用」是同一种自律：那条防**技术副作用**，这条防**方向跑偏**。

> **自检信号**：连续几周的动作全是表现层/工程层（清死代码、调图标、修 bug）——都对、都该做，但要警惕是不是在回避方向决策。
