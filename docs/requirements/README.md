## 1 · 这个目录管什么 / 不管什么

| 管 | 不管（去哪） |
|---|---|
| 需求的**提出**、**改形态**、**砍**、**完成**、**推迟** | 「做了什么」→ [`CHANGELOG.md`](../../CHANGELOG.md) |
| 每次变更背后的**为什么** | 「技术怎么选、代价与取舍」→ [`../adr/`](../adr/)、[`../design/`](../design/)`*-设计.md` |
| 需求的**当前状态**与落点 | 「接下来怎么改代码」→ `.claude/plan/` |
| | 「往哪走、分几个阶段」→ [`../planning/知识飞轮-路线图.md`](../planning/知识飞轮-路线图.md) |
| | 「这个词指什么」→ [`../../CONTEXT.md`](../../CONTEXT.md) |

**一句话分工**：ADR 答「**为什么这么实现**」，本目录答「**为什么要这个东西、它怎么变成今天这样**」。同一件事两边都提到时，本目录只留一句话 + 链过去，不复述。

## 3 · 怎么加一条（三步，接开工指南）

按 [`业务功能开工-图先行指南.md`](../guides/业务功能开工-图先行指南.md) §2 步骤一用思维导图捋完业务之后：

1. **台账**加一行（新需求）或改一行（状态/落点变了）。
2. **演进史**追加一条，写清 `变了什么` / `为什么` / `证据`。
3. **证据**必须是真实的 commit hash 或文件路径。查不到出处的**宁可不写**。

**只有「全套三图 / 减档」触发**（新业务概念、新链路、改 `data.json` 契约、业务规则复杂）。**「免图」档不登记**——小改、修 bug、纯技术重构不是需求级变更，那些进 `CHANGELOG.md`。否则演进史会退化成 git log 的副本，失去价值。
