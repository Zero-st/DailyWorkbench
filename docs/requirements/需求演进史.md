## 2026-08 · 起步：从继承的看板，到写下七项需求

### 2026-08-26 · 基线 —— upstream 快照落地，一批功能以「既有」身份到场
- **变了什么**：仓库从上游快照起步，随后适配本机（数据源、定时刷新、本地服务、个性化）。此时已存在的、日后被砍的功能：课程表（R21）、遥测三件套（R22）、仪表盘/Skill 统计/本周动态（R23）、轻量版 `lite/` 分叉（R24）。
- **为什么**：继承而来，非本仓提出。**它们的需求缘起不可追溯**。
- **证据**：`b63fce5` · `865a561`

### 2026-08-26 · R01 改形态 —— 复盘卡做减法
- **变了什么**：删掉「AI 关注」「明日行动」两栏，改成「今日完成」+ 细线分隔。
- **为什么**：栏目多不等于会写；减少每天要填的格子。
- **证据**：`30751e9`

### 2026-08-28 · R09 提出 + 完成 —— AI 问答要能自己配模型
- **变了什么**：AI 模型管理 + Supabase 云端配置落地；同时接通本地 Obsidian 知识库（成为 R03 的底座）。
- **为什么**：AI 能力要能换供应商、换模型，配置不能写死在代码里。
- **证据**：`7823757`

### 2026-08-28 · R01–R08 提出 —— 七项核心需求**第一次被写下来**（关键锚点）
- **变了什么**：新建 [`../planning/知识飞轮-路线图.md`](../planning/知识飞轮-路线图.md) 与 [`../planning/项目总览-需求与进度.md`](../planning/项目总览-需求与进度.md)，把「输入→捕获→沉淀→蒸馏→输出→复盘反哺」的知识飞轮定为主心骨，并逐条列出用户陈述的七项需求 + 持久化一项。四阶段路线图（Phase 1–4）同时确立。
- **落下的八条**：`R01` 代办+复盘 · `R02` 每日 AI 资讯 · `R03` 好文章沉淀本地库 · `R04` 精炼出口到 ima · `R05` 记录每日灵感 · `R06` 固化成 skill/工作流 · `R07` 蒸馏 up 主经验 · `R08` 持久化/多端/上云。
- **为什么**：此前是「一个看板」，需求在脑子里。写下来之后才有得对照——**本仓所有需求追溯的起点就是这一天**。
- **至今没动过的两条**：`R02` 自落地后再无形态变化（只在 `R13` 扩源时受益）；`R05` **提出 26 天，一次也没推进过**，始终停在「只有一次性 prompt、不留存」。
- **证据**：`af8908b` · [`../planning/项目总览-需求与进度.md`](../planning/项目总览-需求与进度.md) v1.0 §0

### 2026-08-28 · R26 砍 —— ima 不做 API 集成
- **变了什么**：R04「精炼进 ima」的实现路径定为**纯文件交接**（导出到 `待入ima/`，人工导入），明确不做 API 集成。
- **为什么**：ima 没有开放写 API。这是外部事实，不是取舍——属**永久性否决**，写进路线图 §5 的 YAGNI 边界防止日后重提。
- **证据**：[`../planning/知识飞轮-路线图.md`](../planning/知识飞轮-路线图.md) §5

### 2026-08-31 · R07 完成 —— Phase 1 蒸馏库
- **变了什么**：新增「蒸馏库」视图（`js/views/distill.js`）：链接 → skill 六维萃取 → 经验卡 → 落 Obsidian `蒸馏库/`，可筛选检索；后端加 `kb.save(extra)` 与第 9 条 API `GET /api/kb/deposits`。
- **为什么**：七项里挑 Phase 1 先做的判据是「纯本地、代价低、双向门」。
- **证据**：`6fb14d0` · CHANGELOG `[0.5.0]`

### 2026-08-31 · R10 提出 —— 「我该点哪个」成了认知负担
- **变了什么**：做产品/信息架构评审，诊断出 13 个侧边栏入口里**只有约 5 个日用**，其余是重叠或离题。
- **为什么**：用户反馈「产品/模块设计不合理」。评审用 Nielsen 十大启发式 + Krug《别让我思考》定性，不是拍脑袋。
- **证据**：`d7c4265` · [`../design/产品-IA评审.md`](../design/产品-IA评审.md)

### 2026-08-31 · R11 提出 + 完成 —— 存了不用是知识库头号死法
- **变了什么**：新增「今日温故卡」（`js/features/recall.js`，Leitner-lite 间隔重复），让旧蒸馏卡每天主动回到「今日」，三态反馈（👍有用 / ✓已内化 / 打开）。
- **为什么**：`/brainstorming` 诊断出「整条飞轮从没跑通」→ 策略改为**先跑通一条最窄闭环**，选蒸馏闭环、**先攻复用端**。这是全仓唯一写了显式「用户故事」的需求。
- **证据**：`1ccfcd4` · [`../design/温故复用-设计.md`](../design/温故复用-设计.md) §2

### 2026-08-31 · R23 砍 + R21 砍 + R10 部分完成 —— 侧边栏 13 → 9
- **变了什么**：仪表盘拆解下线（交互件并入「今日」）、Skill 统计并入能力速达、本周动态并入动态、**课程表从导航下架**（代码/数据保留）。侧边栏按飞轮顺序重排为「今日 / 飞轮 / 工具 / 设置」。
- **为什么**：先做「改动小 × 可逆 × 收益大」的一批。课程表的理由最直接——**离题**，与知识飞轮无关。
- **证据**：`28cd805` · CHANGELOG `[0.7.0]`

## 2026-09 上旬 · 收敛到 MVP，补上捕获环

### 2026-09-01 · R10 再收敛 + R22 砍 —— 侧边栏 9 → 6
- **变了什么**：只留飞轮五件（今日/资讯/知识库/蒸馏库/AI助手）+ 设置·模型管理。**遥测三件套（系统状态 `ov` / 动态 `sess` / 能力速达 `cap`）从导航下架**，js 文件、`#view-*` section、数据**全部保留**。
- **为什么**：三者都是「看机器在干嘛」，不推动知识在飞轮里流动，对 MVP 是噪音。当时明确判为**双向门**——加回按钮即恢复，所以只下架不删。
- **证据**：`ad81914` · CHANGELOG `[0.8.0]`

### 2026-09-01 · R12 提出 + 首版 —— 捕获环缺一块
- **变了什么**：新增「收件箱」捕获层（`js/features/inbox.js` + 共享平台枚举 `js/core/platforms.js`），localStorage 秒存 → 一键「→蒸馏」预填。当天用真实素材走通**捕获→蒸馏→入库→复用**全链路，落下**第一张真实经验卡**。
- **为什么**：飞轮的输入端一直靠「事后回工作台补录链接」，摩擦太大，看完就丢。
- **证据**：`43ff5ea` · CHANGELOG `[0.8.0]` · [`../planning/复盘-MVP闭环首跑.md`](../planning/复盘-MVP闭环首跑.md)

### 2026-09-02 · R19 提出 + 完成，R25 推迟 —— PC-first
- **变了什么**：删 `mobile/`（Flutter 原生 App）、`twa/`（Android TWA 壳）、APK 构建链与相关脚本。保留 PWA manifest/SW（桌面 PWA 用）。
- **为什么**：战略转向「**先把 PC 端做扎实，功能成型后再回头做移动端**」——一人维护摊不开多端。**回头条件写进 ADR**：出现真实的「手机随时捕获」高频诉求时才重做（R25 ⏸）。
- **证据**：`c7b14ad` · [`../adr/0005-pc-first-drop-native-mobile.md`](../adr/0005-pc-first-drop-native-mobile.md) · CHANGELOG `[0.9.0]`

### 2026-09-02 · R21 / R22 / R23 从「下架」转「彻底删除」——顺带砍掉了 R06 的唯一落点
- **变了什么**：把上一阶段「下架但保留代码」的视图真删：`cap.js`（能力速达）、`ov.js`（系统状态）、`sess.js`（动态）、`js/schedule.js` + `backend/pipeline/push_schedule.py`（课程表），含各自 section、路由、专属 CSS 约 140 行。
- **为什么**：「保留代码」在一人项目里变成了垃圾代码与漂移面；PC-first 收敛的延续。
- **⚠️ 未被记录的副作用（之一）**：R06「把重复劳动固化成 skill」当时唯一的支撑就是「能力速达能查/启动已装 skill」。cap 视图一删，**R06 从 🔧 退回 🚧，至今无任何落点**——这一点在 [`../planning/项目总览-需求与进度.md`](../planning/项目总览-需求与进度.md) 里从未订正过，本次回溯才发现。
- **⚠️ 未被记录的副作用（之二）**：这五个视图正是 `R27` 本机状态遥测的全部消费者，**但喂它们的数据线没有一并删**。`export_data.py` 继续每小时采集 WorkBuddy 的 skills/自动化/模型/记忆/会话/知识库/MCP，写进 `data.json` 八个再也没人读的键——空转到 2026-09-20 才切（见下）。
- **证据**：`c7b14ad` · CHANGELOG `[0.9.0]` Removed

### 2026-09-03 · R24 砍 —— 删 `lite/` 轻量版分叉
- **变了什么**：删 `lite/` 与 `vendor/xlsx.full.min.js`、过期的 `scripts/run_refresh.vbs`。
- **为什么**：lite 与主站有 58 处同名函数重复、其 xlsx 引用路径已断、无实际使用，却让 881KB 的 xlsx 库随 Pages 整仓部署。
- **证据**：`fe68cc9` · [`../adr/0005-pc-first-drop-native-mobile.md`](../adr/0005-pc-first-drop-native-mobile.md) 修订条（`f6a6d90`）

### 2026-09-03 · R12 改形态 —— 捕获从「事后补录」前移到「读帖现场」
- **变了什么**：新增浏览器扩展 `extension/`（MV3，三入口一面板：四站选中浮按钮 / 右键全站可用 / 工具栏 popup，**零站点解析**只用 `getSelection()`+`og:*`）；收件箱从纯 localStorage 升级为**后端真源** `inbox.local.json` + 五条路由，前端改「API 优先 + 离线队列」。条目模型加 `excerpt`+`note`**成对**存放。
- **为什么**：09-01 的收件箱仍要求「离开帖子、回工作台粘链接」，摩擦没消除。另一个收获：**摘录＝人工取材，绕过了小红书/微博反爬抓不到正文的问题**——选中那段本身就是精华。三条候选路（Obsidian Web Clipper / 书签小工具 / 自研扩展）的取舍见设计文档。
- **证据**：`d417eac` · [`../adr/0006-self-built-browser-extension-for-capture.md`](../adr/0006-self-built-browser-extension-for-capture.md) · [`../design/捕获收件箱-浏览器扩展-设计.md`](../design/捕获收件箱-浏览器扩展-设计.md) · CHANGELOG `[0.10.0]`

## 2026-09 中旬 · CHANGELOG 断档期（09-07 → 09-20）

> 📌 **以下所有条目，[`../../CHANGELOG.md`](../../CHANGELOG.md) 均未回写**——它最后一次更新是 `ab70c8d`（2026-09-04）。本段的证据因此取自 ADR 与 `.claude/plan/`，不是凭空补。补 CHANGELOG 是另一件事，见 [`README.md`](README.md)。

### 2026-09-07 · R13 提出 + 首源 —— 资讯源只有两个 API，太窄
- **变了什么**：引入 OpenCLI 作**取数层**信息源，先用 Hacker News 一个源把「subprocess→JSON→映射→`data.json`→前端」端到端跑通；node/opencli 缺失时优雅跳过。
- **为什么**：用户要「更好地获取优质信息」，而当时管道只对接 2 个公开 REST API。**关键架构一线**：OpenCLI 要 Node ≥20.18.1，只能落在取数层，App 本体（前端 + `server.py`）保持 node-free——否则直接违背北极星。
- **证据**：`9362789` · [`../adr/0007-opencli-ingestion-source.md`](../adr/0007-opencli-ingestion-source.md) · [`../../.claude/plan/opencli-mvp-hackernews.md`](../../.claude/plan/opencli-mvp-hackernews.md)

### 2026-09-08 · R13 扩源 —— GitHub Trending + 资讯源可折叠
- **变了什么**：接入第 4 个源；资讯视图的每个源做成可折叠块（折叠态存 localStorage）。
- **为什么**：MVP 验证通过后按计划扩源；源一多，一屏放不下。
- **证据**：`145d281`

### 2026-09-08 · R14 提出 + 完成 —— 蒸馏产物要分价值层级
- **变了什么**：蒸馏指令 fabric 化；经验卡加 `tier` 价值分档，落库并支持按档筛选。
- **为什么**：卡一多，「哪些值得回头看」需要机器可筛的信号，而不是靠记忆。
- **证据**：`6e52b68`

### 2026-09-09 · R15 提出 + 完成 —— 知识库能力要能被外部 agent 调用
- **变了什么**：把知识库能力工具化为 **in-repo MCP server**（`backend/mcp/`，暴露 `kb_search`/`kb_note`/`kb_save`/`kb_tree`/`kb_deposits`），注册进 Claude Code 用户级配置。**不进 App 运行时**。
- **为什么**：蒸馏一直靠人肉复制粘贴在工作台和 agent 之间搬运。工具化后 agent 能直接读写知识库。放仓库内、不进运行时，是为了不让 MCP 依赖污染 App 的零依赖形态。
- **证据**：`7ca30e3` · [`../adr/0008-mcp-integration-layer.md`](../adr/0008-mcp-integration-layer.md) · [`../../.claude/plan/agent-mcp-sidecar.md`](../../.claude/plan/agent-mcp-sidecar.md)

### 2026-09-09 · R16 提出 + 完成 —— 页面上就能指使 agent 干活
- **变了什么**：`/api/agent` 以 subprocess 起无头 `claude -p`，SSE 流式回传；蒸馏楔子接上，AI 对话可带工具。
- **为什么**：页面里此前没有任何驱动 agent 的路子，什么都得回终端。**一条产品级约束（不是技术约束）同时定下**：只读白名单放行，**写库永远走人工闸**。
- **证据**：`161d348` · [`../adr/0009-page-driven-agent.md`](../adr/0009-page-driven-agent.md) · [`../design/功能图解/图解-页面驱动agent.md`](../design/功能图解/图解-页面驱动agent.md)

### 2026-09-09 · R09 改形态 —— AI 助手：从一个导航视图 → 右侧常驻 dock
- **变了什么**：资讯/日报的「讲讲 / 提炼要点 / 存进知识库」原本都走 `aiAsk()` 把一条平文串塞进「AI 助手」整页视图。改为**右侧全局浮遊 dock**（可拖左缘调宽、拖下缘调高、localStorage 记忆尺寸与开合）；「AI 助手」作为独立导航视图被取消。
- **为什么**：跳转即丢上下文，而且只带得过去一个标题。几轮迭代（内联 → 浮遊 dock）后定稿为「随叫随到的对话副驾」。
- **证据**：`e1c339e` · [`../../.claude/plan/ai-copilot-dock.md`](../../.claude/plan/ai-copilot-dock.md)

### 2026-09-10 · R13 扩源 + R18 提出 —— Product Hunt / 少数派，顺带开一条产品拆解线
- **变了什么**：接入第 5、6 个源；同时新建「产品拆解」知识库线。
- **为什么**：扩源之外还有个额外动机——**练产品感**，把每天刷到的产品拆开来写，沉淀成一条线。
- **证据**：`f08b2a5` · [`../../.claude/plan/product-sense-practice.md`](../../.claude/plan/product-sense-practice.md)

### 2026-09-10 · 约束 —— 北极星松绑：「零依赖」→「依赖极简且可撤回」
- **变了什么**：ADR 0010 修订 ADR 0001。原「零构建·零依赖·离线可跑」把三扇**可逆性截然不同**的门捆成一扇；现拆开：**引钉版库 = 双向门**（随时撕掉换回手搓），**引构建步骤 = 单向门**（仍需写 ADR）。同时承认「双击 `index.html` 离线可跑」已名存实亡——真实交付形态早就是 `python -m backend.server` 起本地 http。
- **为什么**：代价是前后端手搓了大量**真·知识重复**的轮子（日期格式化散落 5+ 处、YAML frontmatter 解析 4 份独立实现）。这条约束影响**所有后续需求的可行域**，故收进本文。
- **证据**：`f9cd9bd` · [`../adr/0010-relax-zero-dependency-north-star.md`](../adr/0010-relax-zero-dependency-north-star.md)

### 2026-09-10 · R17 提出 + 完成 —— 不点进去就知道讲啥，还得能按意思搜
- **变了什么**：`enrich`（AI 摘要 + 标签 + 向量，按 url 缓存幂等）→ Zilliz Cloud 向量库；前端叠加式检索面板（词面 + 语义两路）。扩 `data.json` 契约 = 单向门，故写 ADR。
- **为什么**：用户诉求被第一性拆成**两个正交需求**——①「不点进去就知道讲啥」（每条只有 title，HN 的 summary 还只是元信息）②「快速找到我关心的」（当时没有任何搜索）。
- **证据**：`b99d911` · [`../adr/0011-zilliz-semantic-search-for-info.md`](../adr/0011-zilliz-semantic-search-for-info.md) · [`../design/资讯语义检索-设计.md`](../design/资讯语义检索-设计.md)
