# judgment-practice 操作指南

## 0. 这个 skill 解决什么问题

判断力不是靠时间堆出来的，是靠"预测→验证→复盘"这个闭环刻意练习出来的。这个 skill 把这个闭环变成两个可以天天用的动作：

1. **预测-验证卡片**：遇到判断点，先写预测和理由，再看实际结果，记录偏差在哪。
2. **决策日志**：做技术决策时记下决策和关键假设，定期回顾假设是否成立。

对应 [`AI时代程序员成长-心法.md`](../principles/AI时代程序员成长-心法.md) §3「四个杠杆」里最不可替代的那条——**判断（Judge）**：可逆性 + 维护税 + 删除测试；也对应该文 §6「练习节律」表里"每周一条经验进宪章/ADR/skill"这一格的日常抓手。本 skill 不改心法的结论，只是把它落成可执行步骤。

## 1. 什么时候该用

**该记一张预测卡的信号**（符合任一即可，不用等"大事"才记）：
- 让 AI 生成代码/方案前，脑子里已经有一个"我猜它会……"的直觉，但还没验证。
- Review AI 输出时，觉得"这里可能有坑"但不确定。
- 排查 bug 前，已经有根因猜测。
- 任何"我觉得应该没问题"的时刻——这正是最该记录的时刻，因为过度自信最容易在这里暴露。

**该记一条决策日志的信号**：
- 做了一个不那么显而易见的技术选择（选了 A 而不是 B）。
- 这个选择依赖了几个还没被验证的假设（比如"并发量不会超过 X"）。
- 这个决策以后可能需要回头检查"当初的判断对不对"。

**不该用的场景**：日常琐碎操作（改个变量名、修个 typo）不用记；已经是确定性事实、没有"预测"成分的事也不用记。记录的价值在于"事前立场 vs 事后结果"的对照，没有事前立场就没必要记。

## 2. 怎么调用

在本仓库任意位置的 Claude Code 对话里输入：

```
/judgment-practice
```

不带参数会弹出菜单（用 AskUserQuestion）：

1. 记一张新的预测卡
2. 补全一张预测卡的结果
3. 记一条新的决策
4. 回顾（review）

也可以直接带自然语言跳过菜单，比如：

```
/judgment-practice 记一条决策
/judgment-practice 补一下今天那条预测
/judgment-practice review
```

> 这个 skill 设了 `disable-model-invocation: true`，**不会被模型自动联想触发**——不敲 `/judgment-practice` 它就不会跳出来打断你。这是刻意的取舍：换来不占对话上下文，代价是你得自己记得用（见第 5 节的节奏建议 + 第 6 节的被动提醒兜底）。

## 3. 四个操作分支怎么走

### 3.1 记一张新预测卡

会依次追问三句话，直接口语回答即可：
1. "判断的问题是什么？"
2. "你的预测是什么？"
3. "为什么这么预测？"

写完后会提示你"等看到实际结果后回来选 2 补全"。

### 3.2 补全一张预测卡的结果

会自动找出最近几条还没写结果的记录列给你选，选中后追问：
1. "实际结果是什么？"
2. "偏差在哪——你觉得判断错在哪一步？"

回答后原地写回那条记录（不是新建一条），方便以后预测和结果并排对照着看。

### 3.3 记一条新决策

依次追问：
1. "这次决策是什么？"
2. "关键假设有哪些？"（1-3 条，越具体越好）
3. "备选方案是什么、为什么没选它？"

### 3.4 回顾（review）

汇总最近的记录：本周新增了几条预测卡、补全了几条、有没有反复出现的偏差模式；决策日志里有没有到期该回顾的假设。回顾中会问你"这个假设现在看成立吗"，回答后原地回填结论。回顾流程结束时会自动更新"上次回顾"时间戳（这是第 6 节被动提醒机制的关键，不用你手动管）。

## 4. 记录存在哪里

- 预测-验证卡：`.claude/skills/judgment-practice/data/predictions.md`

是否把这两个文件提交到 git，由你自己决定——skill 不会自动 commit。

## 5. 建议使用节奏

不强制，仅供参考，用顺手了自己调整：

| 频率 | 建议动作 |
|---|---|
| 高频（嵌入日常） | 有判断点就随手记预测卡，不用等到"重要"才记——次数越多，校准越快 |
| 每周 | 用 `review` 看一遍本周偏差，回填决策日志里到期的"周回顾结论" |
| 每季度 | `review` 会提醒是否到期，挑 2-3 条较早的决策写"如果重来" |

## 6. 常见问题

**忘记敲命令、很久没回顾了怎么办？**
不用专门记着回顾日期——只要你还在正常记预测卡/决策（分支 1/2/3），skill 会顺手检查两个文件头部的"上次回顾"时间戳，超期会在操作做完后追加一句提醒。真正完全不用这个 skill 的话，提醒也就不会触发，这是"仅手动触发"设计天然的代价。

**记录攒多了不好翻怎么办？**
用 `/judgment-practice review`，它会做汇总而不是让你逐条翻文件。

**这两个文件会不会被误删/污染知识库？**
不会，它们是本仓库 `.claude/skills/judgment-practice/data/` 下的普通 markdown，跟项目里的 Obsidian 知识库（`kb_save` 那套）完全独立，互不影响。

**以后想加事故复盘精读 / code review 找茬 / 独立季度回顾这三项练习怎么办？**
当前 skill 明确只做预测卡+决策日志两项（见 `SKILL.md` "边界"节）。想扩展时在 `judgment-practice` 里加新分支，或另开 skill，到时候记得回来更新本文档。
