# 项目自评打分 · 指南（资深式：事前目标 → 事后证据 → 决策/结果分列 → 校准）

> 性质：**操作指南（how-to）**。教「一个里程碑收尾时，怎么像资深产品经理一样给自己的项目打一张经得起追问的分」。
> 归位真源：[`../README.md`](../README.md)（后缀 `-指南` → guides；每次打分结果按 `复盘-*` 前缀进 `planning/`）。心法上位：[`../principles/开发心法-多维思维总纲.md`](../principles/开发心法-多维思维总纲.md) §4（事前「造不造」的门，本指南**不重列**）、[`../principles/产品思维-心法.md`](../principles/产品思维-心法.md) §1（五根判断轴 = 结果层的问法）、[`judgment-practice操作指南.md`](judgment-practice操作指南.md)（预测卡 = 校准环）。质量层取证方法承 [`../design/工作台走查评审-v0.8.0.md`](../design/工作台走查评审-v0.8.0.md)。
> 一句话：**分数是副产品，「事前目标 vs 事后实际」那两列才是全部价值**；没证据的格子写 N/A，不编。

---

## 1 · 何时打分 · 何时不打

| 场景 | 打不打 | 说明 |
|---|---|---|
| 里程碑 / Phase 收尾（路线图一个阶段完结） | **打** | 结果层对表该阶段开工时写下的目标 |
| dogfood 冲刺结束（如 [`../planning/复盘-dogfood冲刺-W1.md`](../planning/复盘-dogfood冲刺-W1.md)） | **打** | 冲刺的退出指标就是现成的事前目标 |
| 心法 §5 自检信号亮起：连续数周动作全在表现层 / 工程层 | **打** | 这时最容易用「做了很多」掩盖「没验证」 |
| 每周例行 | **不打** | 一人项目仪式别淹死自己；周级只记预测卡和摩擦 |
| 刚上线一周内 | **不打** | 新鲜感效应会抬高一切，留存要等曲线走平（§9） |

> 判据：**有事前目标可对表才打**。没有事前目标时先补一份「下期事前目标」（§8），下次再打——第一次打分的主要产出往往就是这份目标。

---

## 2 · 五条底线

**评结果，不评产出。** 上线了几个功能不算分，用户行为或业务指标变了多少才算分。「做完了」是 0 分的起点。commit 数、功能数、文档篇数只能进成本层，不能进结果层。

**标准先于结果。** 打分表在开工前填好目标和放弃线（kill criteria），事后只填「实际」与「证据」两列。事后才定标准等于搬门柱。本仓的事前目标来源：冲刺复盘的退出指标、路线图阶段的验收句、预测卡。

**决策质量和结果质量分开算。** 当时信息下的好决策加坏运气不扣决策分，蒙对的不加分（Annie Duke 称把二者混为一谈为 resulting）。所以八列卡里「分」和「决策质量」是两列（§7）。

**证据分级，无证据标观点。** 每个分数旁写证据来源与等级（§5）。凭感觉的分显式标 `观点`，且有上限。

**先过硬门，再加权打分。** 「需求真伪」1 分时界面 5 分救不回来。硬门任一为否不进打分；总分用几何加权而非算术平均，让质量层补不了结果层（§6）。

---

## 3 · 打分七步

1. **锁事前目标来源**（带定标日期）：找到这一期开工时写下的目标——复盘退出指标 / 路线图验收句 / 预测卡。找不到 → 这次不出总分，只做 §8 的「下期事前目标」。
2. **过项目级硬门**（§4 G）：三门逐条给证据，状态写 过 / 不过 / 未判定。
3. **逐维取证**：每个维度先写「证据来源 + 等级 + 取证日期」，再看分。**先证据后分数**，顺序不能反。
4. **按锚点打分**：对照 §6 的 1/3/5 锚点打 1–5；证据拿不到写 N/A；证据只到「观点」级写 `N/A · 观点(≈k)`。
5. **填决策质量**：每行按 §7 的 A/B/C 三档，可分「目标设定 / 测量流程」两段。
6. **算总分与置信带**（§6 公式）：按发布规则决定给点估计还是只给区间。
7. **写下期事前目标**（§8）：3–5 条可观察指标 + 放弃线 + 对表日期，并用 `/judgment-practice` 分支 1 记成预测卡；下次打分时用分支 2 回填。

## 4 · 三层结构与维度表

### G · 硬门（不计分，任一为「不过」→ 总分为 0）

三门原文见 [`开发心法`](../principles/开发心法-多维思维总纲.md) §4 第 1 关，那里是**按功能**问的；套到**整个项目**时按下面适配：

| 门 | 项目级问法 | 证据从哪来 |
|---|---|---|
| 频率门 | 这一期我**真实使用**工作台 ≥ 2 天 / 周吗？ | 使用产物的日期（捕获 / 蒸馏卡 / 复盘键），**不是 git commit**（那是建造者活动） |
| 飞轮门 | 这一期的交付落在飞轮哪一环（输入→捕获→沉淀→蒸馏→复用）？ | 对照 [`知识飞轮-路线图`](../planning/知识飞轮-路线图.md) §1 逐项归环 |
| 人在环中门 | 有没有交付是「替我思考」而非「帮我思考」？ | 照原文 |

状态三态：**过 / 不过 / 未判定**。「未判定」（例：使用数据拿不到）不等于「不过」，但触发 §5 的发布规则。

### O · 结果层（「做对了事吗」，3 维，权重最大）

| 维度 | 在问什么 | 常用指标 | 证据来源 | 出处 |
|---|---|---|---|---|
| 价值 · 复用留存 | 卡 / 内容落库后**有没有被回头用**？替换了什么旧体验？（问法用 [`产品思维-心法`](../principles/产品思维-心法.md) §1 的「用户价值」「需求真伪」两轴） | 近 30 天被主动重开的卡数、温故点开次数、「因为查卡而做了决定」的实例数 | 行为记录（localStorage `wb_recall`、复盘 / ADR 里的引用） | Sean Ellis「没了会很失望」测试；Google HEART 的 Retention |
| 飞轮闭环完成度 | 五环是否都用**真实内容**转过、转得多勤？（本项目的北极星指标） | 真卡**流量**（区间内新增）、收件箱→已蒸馏转化率、每周整转圈数 | 磁盘产物（`_index.jsonl`、按日期目录）、`inbox.local.json` 状态字段 | 路线图 §1 飞轮模型 |
| 学习 · 判断校准 | 这一期**想对了吗**？预注册的东西被测量了吗？ | 预注册指标回填率、预测卡数与补全率、能否写出一条反复出现的偏差模式 | `judgment-practice/data/*.md`、复盘文件状态 | Brier score（校准） |

### Q · 质量层（「做好了吗」，4 维）

直接沿用 [`工作台走查评审-v0.8.0`](../design/工作台走查评审-v0.8.0.md) §1 的四层与 1–5 刻度，和历史基线可比：**产品功能 / UI 视觉 / 交互体验 / 技术健壮性**。取证方法也沿它：chrome-devtools 真机走查 + Nielsen 十大启发式 + Krug《别让我思考》。

> v0.8.0 的七维 0–100 评分卡（`reference/devhtml/产品评分卡-v0.8.0.html`）**退役**：它是等权算术平均、无结果层、与四层 1–5 刻度混用。新旧分数**不可比**，只比维度排序。

### C · 成本层（扣减，上限 0.3）

| 项 | 0 | 0.1 | 0.2 |
|---|---|---|---|
| 维护税（[`心法`](../principles/开发心法-多维思维总纲.md) §4 第 2 关） | 本期无新增长期负担 | 新增 1 个要长期维护的外部依赖 / 管道 / 双份真源 | ≥ 2 个 |

| 项 | 0 | 0.05 | 0.1 |
|---|---|---|---|
| 逃逸缺陷 · 文档漂移 | 无 | 1 处已知（文档写的与现实不一致 / 逃逸 bug） | ≥ 2 处 |

节奏（commit 数、feat 占比）只在成本层作**背景**记录，不折算成分。

## 5 · 证据等级与 N/A 规则

| 等级 | 例子 | 能打几分 |
|---|---|---|
| 行为记录 | 磁盘产物、日志、localStorage 状态、文件 mtime、git 历史 | 1–5 |
| 留存曲线 / cohort | 按周分组的回访 | 1–5 |
| 对照实验 | A/B、前后对照 | 1–5 |
| 访谈 / 工单原话 | 一人项目 = 摩擦清单里的**具体动作** | 1–5 |
| 问卷 / NPS | — | 1–4 |
| 观点 | 「我感觉挺好用」 | **上限 3**，且写成 `N/A · 观点(≈k)` |

**N/A 规则**（不知道 ≠ 差）：
- N/A 维度**不进点估计**（其余维度重归一取均值）。
- **置信带**：N/A 维度分别代入 1 与 3 重算总分，得 `[L, U]`。带宽本身就是「缺遥测」的可视化；收窄它的唯一办法是补证据。
- **观点上限**：证据只到观点级的维度，同 N/A 处理，带上界取 3。
- **发布规则**：硬门有「未判定」**或**结果层覆盖率 c（已计分维 / 3）< 0.5 → 不发布点估计，总分栏只写置信带并标「结果层不可评」。

## 6 · 刻度 · 锚点 · 总分算法

```
s → s/5                      1–5 映到 0.2–1.0，避免 0 退化
O = mean(结果层已计分维)     Q = mean(质量层四维)      C = 成本层扣减（≤ 0.3）
总分 = 100 × G × O^0.6 × Q^0.4 × (1 − C)
置信带 = 把 N/A 维分别代入 1 / 3 重算 → [L, U]
```

**为什么几何加权**：结果层指数 0.6 > 质量层 0.4 保证「结果层 ≥ 50%」；乘法让质量层补不了结果层。算例：结果层全 1 分、质量层全 5 分 → 几何 **38**，而同权重的加法给 **52**。

### 锚点 · 结果层（写成可观察事实，一人项目适用）

**价值 · 复用留存**
- **1**：卡落库后无一张被重开；温故卡浮现无点开记录或无从知道；近 30 天 0 次「因为查卡而做了决定」。
- **3**：近 30 天 ≥ 3 张不同卡被主动重开（有记录），且 ≥ 1 次能写出「卡 X 影响了决定 Y」（落在复盘 / ADR / CHANGELOG）。
- **5**：温故点开每周 ≥ 3 次、连续 4 周（行为记录）；≥ 1 张卡被引用进 ADR 或新功能决策；删除测试成立——拔掉蒸馏库能说出哪个日常动作会断。

**飞轮闭环完成度**（五环：输入→捕获→沉淀→蒸馏→复用）
- **1**：只有单环有真实数据，或闭环只用测试数据跑过；真卡 ≤ 1。
- **3**：五环各用真实内容跑通至少一次（[`复盘-MVP闭环首跑`](../planning/复盘-MVP闭环首跑.md) 那种）；真卡 ≥ 5；但 ≥ 1 环靠手动搬运（复制指令 → skill → 粘回）。
- **5**：近 4 周每周至少整转 1 圈（捕获 / 蒸馏 / 温故点开各有当周记录）；收件箱→已蒸馏转化率能报出数字；有 ≥ 1 个「复盘反哺」实例。

**学习 · 判断校准**
- **1**：预注册指标 0 条被测量；预测卡 0 条关于产品判断。
- **3**：预注册指标 ≥ 半数被回填；≥ 3 张产品判断类预测卡且已补结果。
- **5**：预注册指标全部回填；预测卡 ≥ 10 且能写出一条反复出现的偏差模式；至少 1 条决策日志写过「如果重来」。

### 锚点 · 质量层（四维通用，细则看走查评审）

- **1**：某一步**无法完成**（阻断），或大面积缺陷（如整屏图标 tofu、移动端导航不可用）。
- **3**：可用但有摩擦——要想一下、要绕一下；有已知小 bug 但不阻断。
- **5**：不用想（Krug）；6 视图零 console error；空态 / 错误态 / 劣化态都有友好文案。

## 7 · 决策质量栏怎么填

| 档 | 判据 | 例 |
|---|---|---|
| **A** | 过三门 + 有量化目标 + 有放弃线 | 「dogfood 一周，真卡 ≥ 5，写不出结论句就不开工」 |
| **B** | 过三门，但无量化目标 | 「先把闭环跑顺」 |
| **C** | 无事前过程，事后合理化 | 上线后才找理由说它有用 |

可拆成「目标设定 A / 测量流程 C」两段写——**目标定得好但没去量**是一人项目最常见的组合，值得单独暴露。

## 9 · 自评作弊清单（打分前逐条自问）

| 作弊方式 | 表现 | 解药 |
|---|---|---|
| Vanity metrics | 用只涨不跌的数（总条目、总 commit、总篇数）当成绩 | 只有**流量**和**回头率**进结果层 |
| 按努力打分 | 熬了多少夜、写了多少行 | 努力进成本层背景，不进分 |
| 无放弃线 | 说不出「什么结果算失败」 | §8 每条目标配放弃线 |
| 上线当周打分 | 新鲜感抬高一切 | §1：刚上线一周内不打 |
| Cherry-pick 轶事 | 一两条好评代表全体 | 证据等级列写清楚是几条、哪来的 |
| 无反事实 | 不问「没做这个会怎样」 | 决策质量栏里写备选方案 |
| **存量当流量** | 用今天的总卡数回答「这一周新增了几张」 | 事后实际列按**区间日期截断**，存量另注 |
| 自恋（一人项目专项） | 用户就是自己，感觉代替记录 | 行为记录优先；观点上限 3；删除测试与维护税见心法 §4 |
