## 0 · 为什么补这份

本仓的**治理层**（需求台账 28 条 + 演进史、15 篇 ADR、路线图、自评刻度、预注册放弃线、使用量尺子）比多数团队完整，但**执行层缺位**，实测证据：

| 证据 | 数字 |
|---|---|
| `.claude/plan/` 里零勾选框、零状态字段的计划 | 22 / 24 篇 |
| 提交里带周次 / 任务号的 | ~9 / 112 条 |
| `docs` 类提交 vs `feat` 类提交 | 33 (29.5%) > 26 (23.2%)，非新功能占 60% |
| `next-steps-dogfood-w1.md` 第 2 步排了没执行且无人发现 | 17 天（09-03 → 09-20） |
| [`../planning/复盘-dogfood冲刺-W1.md`](../planning/复盘-dogfood冲刺-W1.md) 回填率 | **0 / 7** |

**根因不是规划不足，是计划的最小单位是「周」而周内动作藏在长散文里**——于是任何时刻都答不出「这份计划执行到哪了」。本文补的就是这一层，且**只补这一层**：路线图、台账、ADR、自评卡全部不动。

> ⚠️ 本文自身就是元工作。它的护栏是 §8 的放弃线——**和 ADR 0015 让尺子受自己约束是同一个道理**。

## 1 · 三层节拍

| 节拍 | 做什么 | 落点 | 耗时 |
|---|---|---|---|
| **日** | 在工作台「今日」视图的复盘框写**一句话**：今天动了什么、卡在哪 | 产品自己（`review_save`） | ≤30 秒 |
| **周**（周五） | 四问仪式（§6） | [`../planning/复盘-dogfood冲刺-W2-W4.md`](../planning/复盘-dogfood冲刺-W2-W4.md) 当周小节 | 15 分钟 |
| **期**（冲刺末） | 对表 + 打自评卡 + 执行放弃线 | `../planning/复盘-项目自评打分-YYYY-MM.md` | 已有流程 |

**日进度刻意不新建 markdown 日志**：上一次的 7 行手填表 0/7 回填，死因是「填它要离开工作台、开编辑器、切上下文」。写进产品的复盘框一举三得——不新增习惯、产生 `review_save` 埋点、直接喂自评卡 #4。

**作战板的勾选是事件驱动，不是每日义务**：做完一条就勾，没做完就别动它。把勾选变成日常打卡，它就会变成第二张空表。

## 2 · 完成度的三个定义

**一人项目的完成度不该来自工时估算，该来自门禁计数。** 三个层级都从现有数据算得出来，一个估算都不需要：

| 层级 | 公式 | 数据源 | 对外报 |
|---|---|---|---|
| **当期完成度** | 出口门禁勾选数 / 总数 | 作战板 §② | ✅ 只报这个 |
| **需求完成度** | ✅ 条数 / (合计 − ✂) | [需求台账](../requirements/需求台账.md) §4 汇总表 | 期末报 |
| **周门通过率** | 通过的周门 / 已过周数 | 冲刺复盘表的「门」列 | 期末报 |

> 2026-09-21 基线：需求完成度 **16 / 23 = 70%**（✅16 · 🔧3 · 🚧3 · ⏸1，合计 29 含 ✂6；本批新增 `R29` 后的数，建本文时为 15/22 = 68%）。数随台账走，**别在这里维护第二份**。

**明确不做**：甘特图 · WBS 工时估算 · 燃尽图。

> **2026-09-21 订正**：原文还列着「完成度仪表视图」。工作台已加「项目进度」视图——它置顶的是**放弃线倒计时**（判决压力）而非成就展示，与被砍的 `ov`/`cap`/`sess`（看机器在干嘛）性质不同。论证与预注册放弃线见 [ADR 0016](../adr/0016-in-app-progress-view.md)。**仍然不做**甘特/工时估算/燃尽图。

## 3 · DoD · 完成的定义

一条任务能勾 `[x]`，**四款必须同时满足，缺一退回 `[~]`**：

| # | 条件 | 怎么验 |
|---|---|---|
| ① | 代码 / 文档已落盘并 commit | `git log` 看得到 |
| ② | 跑过 [`../开发测试规范.md`](../开发测试规范.md) 的**对应档位**门禁（小改不必全量，但档位要说得出口） | 命令输出全绿 |
| ③ | 作战板那一行写了**一句可验证的验收事实**（不是「做完了」） | 人读一眼 |
| ④ | 若改了需求状态，[台账](../requirements/需求台账.md) + [演进史](../requirements/需求演进史.md) 已回写 | 两份文件的 diff |

**为什么要第 ③ 款**：「重构完了」不可验证，「`export_data.py` 584→97 行且 `pytest -q` 全绿」可验证。写不出可验证事实，多半是这条任务本身没定义清楚。

**状态符号**：`[ ]` 未开 · `[~]` 在做 · `[x]` 完成 · `[-]` 放弃（**必须补一句为什么**——放弃不写理由，下次会原样再排一遍）。

## 4 · 作战板怎么用

位置 `.claude/plan/作战板-<期>.md`（**归 `.claude/plan/` 不进 `docs/`**，依 [`../文档规范.md`](../文档规范.md) §3「`docs/` = 沉淀的项目知识；`.claude/plan/` = 过程性的实施计划」）。一期一张，过期不删只封存。五段：

| 段 | 内容 | 更新时机 |
|---|---|---|
| **① 本期承诺（基线）** | 这一期交什么 + **明确不交什么** | 开期定，**期中不改**（要改就在 §⑥ 记一行变更） |
| **② 出口门禁** | 可勾选的验收条目 → **当期完成度的分母** | 达成即勾 |
| **③ 本周任务（≤5 条）** | `[ ] 描述 — 验收：<一句话可验证事实>` | 周一定，随时勾 |
| **④ 风险与假设登记册** | 每条带「触发信号 / 应对 / 状态」 | 周五过一遍 |
| **⑤ 偏离记录** | 做了计划外的事就记一行 | 发生即记 |

两条纪律：

- **②③ 的条目只搬不重写**——冲刺计划仍是「为什么这么排」的真源，作战板只管「做到哪」。两处各写一份就会漂移（[项目总览](../planning/项目总览-需求与进度.md) §0 已经因此迁走过一张表）。
- **③ 每周上限 5 条**。排不下说明这周想干的事超过了一个人的带宽，砍到 5 条比排 8 条再完成 3 条诚实。

### 4.1 · 换期清单（每期一次，约 10 分钟）

一期一张板。**旧板不删只封存**——历史证据是这个项目做判决的依据（上一份 0/7 回填的空表就是留作证据的）。

1. 复制 [`../../.claude/plan/作战板-模板.md`](../../.claude/plan/作战板-模板.md) 为 `.claude/plan/作战板-<YYYY-MM>.md`。**文件名必须是这个形状**——`config.board_path()` 只认 `作战板-\d{4}-\d{2}.md`（模板与归档因此天然不会被误选）。
2. 改头部三行：标题 / `建板` / **`对表日`** / **`周表：[...](...)`**。后两项是机器读的——对表日决定页面倒计时，周表链接决定去哪读周门。**漏改对表日，页面会显示上期的倒计时**（会标成 `source: fallback`，但别靠它兜底）。
3. §⓪ 层一：从 [`../planning/知识飞轮-路线图.md`](../planning/知识飞轮-路线图.md) §3 同步阶段状态。只在阶段真变了时才有改动。
4. §⓪ 层二：填本期周次、区间、**可量化的周门**。内容未定的周如实写「待 X 摩擦决定」，**不编任务填满它**。
5. §② 搬本期出口门禁（从冲刺计划搬，**只搬不重写**）；§① 写承诺与「明确不交」。
6. 上期未完成项迁入 §②③，**标注来源**（如「承自 2026-09 W0-3」），否则期末分不清是新欠的还是老欠的。

**改完自检**：`python -m pytest -q -k progress` 全绿（表头没被改坏），再开一次工作台进度视图确认三层数字都有值。

**表头是解析契约**：§⓪ 两张表的列名、各段 `##` 标题都不能改字。改坏了 `pytest` 直接红（`test_progress_parses_the_current_real_board`），页面顶部也会显示「某段解析失败」——**两道保险都不靠人记得**。

---

**碎片 backlog 不合并**：走查评审的 `X/T/U/P`、自评卡的 `D1–D7`、台账的 `R` 三套编号互不冲突，**强行统一是纯搬运**。作战板 §③ 每周从中挑 ≤5 条做**收口**即可。

见 [`../版本管理规范.md`](../版本管理规范.md) §2：commit body 可加尾行 `Refs: R28, W1-3`（需求编号 / 作战板任务号）。

```bash
git log --grep="Refs: R28"          # 这条需求花了哪些提交
git log --grep="Refs:" --oneline    # 这期有多少活是排过的
```

## 6 · 周五 15 分钟仪式 · 四问

**不新增时间**，在现有仪式上扩两问。落点是冲刺复盘文档的当周小节。

```bash
python -m backend.pipeline.usage_report --days 7
```

| # | 问 | 答在哪 |
|---|---|---|
| 1 | 这周的使用量表 | 粘报表输出（已有） |
| 2 | 摩擦按次数排序 + **结论句（人写）** | 已有 |
| 3 | **作战板勾了几条 / 没勾的为什么** | 新 |
| 4 | **做了几件计划外的事 · 元工作是否过半** | 新 |

第 4 问的数字由报表末尾的「工作构成」段直接给出（第五源 `git log`）：

```
### 工作构成 · 2026-09-14 起（注意力花在哪）
- 共 27 条提交：docs 10 · feat 8 · refactor 3 · chore 2 · fix 2 · i18n 2
- 元工作（docs/chore/refactor/style）占比 56% ⚠ 过半——周五第 4 问要写一句为什么
```

**只提示不判红**——判红会变成新的假绿动力（与宪章禁 `|| true` 同一条理由）。超过 50% 不是错，但**必须写一句为什么**。这是把[心法 §5](../principles/开发心法-多维思维总纲.md) 那条「连续几周动作全在工程层要警惕」的主观自检，换成客观数字。

> 一人项目的稀缺资源是**注意力**不是工时，所以「成本管理」这一格量的是元工作占比，不做人天估算。

## 7 · 发版节奏

- **每个冲刺末发一版并打 tag**（`git tag -a vX.Y.Z`），规则见 [`../版本管理规范.md`](../版本管理规范.md)。
- 起点 `v0.11.0`，**不追溯补 v0.7–v0.10 的旧 tag**（收益低、易错；仓里目前只有一个历史 tag `apk-1`）。
- 触发信号：`CHANGELOG.md` 的 `[Unreleased]` 堆了 **2 周以上或含 MINOR 级新增**就该发版。2026-09 这次的教训是它停在 0.10.0 / 09-03 达 17 天。

## 8 · 本机制自身的放弃线（预注册 · 2026-10-17 与冲刺同日执行）

| 指标 | 放弃线 | 动作 |
|---|---|---|
| 作战板被更新的天数（28 天窗口） | **< 8 天** | 删作战板，承认「不需要任务级追踪」，回到纯计划文档，本文标「已废弃」 |
| 周五第 3、4 问回填 | < 2 周 | 砍掉这两问，只留报表 |
| 元工作占比告警 | 触发 ≥3 次但从未写原因 | 删 `usage_report` 的工作构成段 |
| 「项目进度」视图 `progress_open` | < 4 次 | 删视图 + 两个写端点 + `progress.py` + `.pg-*` + 侧栏项，退回 CLI 报表（ADR 0016）|

怎么量：

```bash
git log --since=2026-09-21 --pretty=%ad --date=short -- .claude/plan/作战板-2026-09.md | sort -u | wc -l
```

**尺子自己也受同一把尺子约束**——这条是 ADR 0015 立的先例，不是本文的新发明。

## 9 · 与其它文档的分工（别重复、别打架）
