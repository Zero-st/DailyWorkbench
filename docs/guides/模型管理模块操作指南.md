# 个人工作台 · AI 模型管理模块 操作指南

> 适用路径：`E:\AITools\DailyWorkbench`
> 实测环境：Windows + 本机 Edge + `server.py`（端口 8080）
> 文档生成日期：2026-08-27

---

## 0. 这个模块解决什么

工作台内置「AI 助手」聊天框，但**直连第三方大模型 API 会被浏览器跨域（CORS）拦截**，且每次换浏览器/清缓存就要重配 Key。本模块解决两个问题：

1. **统一管理**：在一个界面里增删改查多家 AI 平台（OpenAI / 火山方舟 / DeepSeek / 智谱 …）及其模型，一键切换「当前模型」。
2. **不走直连**：所有请求经本机 `server.py` 的 `/api/chat` 代理转发，Key 只存本机，**不暴露给第三方站点**。
3. **持久化**：配置默认存浏览器 `localStorage`；可选接 Supabase 云库实现跨设备不重配（见第 6 节）。

## 1. 启动工作台

模型管理依赖本地服务器（`server.py` 提供静态页 + 代理），**不能直接双击 `index.html`**（那样没有代理，`/api/chat` 不通）。

```bash
cd E:\AITools\DailyWorkbench
python -m backend.server 8080
```

启动成功后终端显示：

```
Workbench: http://localhost:8080  (Ctrl+C stop)
POST /api/refresh -> local_refresh.py
POST /api/chat   -> AI proxy
```

浏览器打开：**http://127.0.0.1:8080**

> 若端口被占，把 `8080` 换成其他端口（如 `8090`）。
> 服务器关掉后页面还能看，但「AI 助手」发消息会失败。

---

## 2. 进入「模型管理」

左侧导航栏 → 点 **🧠 模型管理**，主区显示：

- 顶部一行：**「当前 AI 助手正在使用：⚙️ <平台> · <模型>」**（即 AI 助手此刻用的模型）
- **➕ 添加模型** 按钮
- 已保存的模型卡片列表，每张卡含：平台图标、显示名、模型名、激活状态、「编辑 / 删除」按钮

---

## 3. 添加 / 配置一个模型

点 **➕ 添加模型**，弹出配置框。字段说明：

| 字段 | 说明 | 注意 |
|---|---|---|
| **提供商** | 下拉选平台（见下表）。选后自动填 API 地址 + 模型列表 | 选「自定义 OpenAI 兼容」可手填任意地址 |
| **显示名称** | 卡片上展示的名字，建议「平台 · 模型」格式 | 例：`火山方舟 · glm-5.3` |
| **模型名称** | 下拉选预设模型；或切到「自定义模型名称…」手填 | 填平台要求的模型 ID，如 `glm-5.3` |
| **API Key** | 平台密钥 | 仅存本机浏览器，不发出去（代理用服务端转发） |
| **API 地址** | OpenAI 兼容的 `chat/completions` 完整地址 | **必须带 `/chat/completions` 后缀**，否则 404 |
| **仅支持 OpenAI 兼容协议 API** | 提示条 | 当前代理走 OpenAI 协议格式 |

**标准步骤（以火山方舟 Coding Plan 为例）：**

1. 提供商 选 **火山方舟 Coding Plan**
2. 显示名称 填 `火山方舟 · glm-5.3`
3. 模型名称 选 `glm-5.3`
4. API Key 粘贴你的方舟 Key（控制台 → _API 访问_ → 创建密钥）
5. API 地址 已自动填好 `https://ark.cn-beijing.volces.com/api/coding/v3/chat/completions`（**确认末尾是 `/chat/completions`**）
6. 点 **保存**
7. 在卡片上点 **设为当前**，让它成为 AI 助手默认模型

> ⚠️ 最常见报错就是「API 地址少了 `/chat/completions`」→ 代理转发到错误路径返回 404。选预设会自动带全路径，手动填务必核对。

## 5. 在 AI 助手里使用

1. 左侧点 **🤖 AI 助手**
2. 顶部显示 **「当前模型：<平台> · <模型> · 已配置」**（如未配置会提示去加 Key）
3. 输入框输入问题，Enter 或点 **发送**
4. 请求链路：`浏览器 → /api/chat（本机 server.py）→ 平台 API → 原路返回`
5. 历史对话自动存本机，刷新/重开不丢

## 6. 让配置跨设备 / 不重配（可选：Supabase）

`localStorage` 跟着浏览器走，清缓存、换浏览器、换电脑就会丢。已内置 Supabase 云端存储支持（代码已就位，等你提供凭证即生效）。

**接入步骤：**

1. 注册 Supabase（免费），新建项目
2. SQL Editor 执行仓库里的 `supabase_schema.sql`（建 `model_configs` 单表）
3. 拿两个值：**Project URL** + **service_role key**（Settings → API，注意是 `service_role` 不是 `anon`）
4. 二选一放置（任选其一）：
   - 环境变量：`SUPABASE_URL` + `SUPABASE_SERVICE_KEY`
   - 或本地文件 `E:\AITools\DailyWorkbench\supabase.local.json`：
     ```json
     { "url": "https://xxxx.supabase.co", "serviceKey": "eyJ..." }
     ```
     （该文件已加入 `.gitignore`，不会进版本库）
5. 重启 `server.py`
6. 首次打开会自动把现有本地配置同步上云；之后增删改实时写云

**安全模型**：Service Key 只在 `server.py` 服务端持有，前端不接触 Key，和 `/api/chat` 一致——API Key 全程不出本机/服务端。

## 7. 故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| AI 助手回复 `Failed to fetch` | 浏览器直连被 CORS 拦（没走代理） | 确认用 `server.py` 启动并访问 `http://127.0.0.1:8080`，不是 `file://` 直开 |
| 代理返回 404 | API 地址缺 `/chat/completions` 后缀 | 编辑配置，补全完整路径 |
| 代理返回 401 | API Key 错误/失效 | 重新到平台生成 Key 并保存 |
| 改了配置页面没变 | Service Worker 缓存旧代码 | 关掉标签页重开，或 `Ctrl+Shift+R` 硬刷 |
| 换浏览器/清缓存后配置没了 | 用的是 localStorage，未接 Supabase | 见第 6 节接云端，或同浏览器同 profile 使用 |
