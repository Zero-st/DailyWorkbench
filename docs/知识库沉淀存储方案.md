# AI 工作台内容沉淀 · 知识库存储方案

> 版本：v1.0　制定：2026-08-28
> 适用：`E:\AITools\DailyWorkbench` 工作台 → 沉淀到 Obsidian 知识库
> 关联：`Supabase上线操作指南.md`、知识库接入实现计划（plan 文件）

---

## 1. 目标

为工作台各模块产生的内容（复盘、AI 对话精华、AI 日报、新闻精选、会话存档、手写笔记等）建立**统一、规范、可追溯**的沉淀存储方案，确保：
- 所有沉淀内容只落到唯一根目录，不散落；
- 目录按「模块 / 日期 / 内容」三级组织，可按模块与日期快速浏览检索；
- 命名稳定无歧义，永不覆盖既有文件；
- 每次保存完整记录路径与命名信息，可追溯。

本方案是知识库接入功能（只读浏览父库）的**写入侧**配套：沉淀目录 `AI工作台沉淀内容` 本身位于父库 `E:\AiknowledgeBase\knowledgeBase\` 之下，沉淀进去的笔记会自动成为知识库面板可浏览/可检索/可双链的一部分。

## 2. 存储根路径（唯一）

```
E:\AiknowledgeBase\knowledgeBase\AI工作台沉淀内容\
```

- **唯一落点**：任何「存进知识库」动作都写入此根目录，禁止写到其他位置。
- 该目录已存在（空），作为工作台写入落点；父库其余内容为只读引用源。
- 路径在工作台后端通过 `kb.local.json` 的 `depositRoot` 字段配置（与 `vault` 并列），可改不可硬编码。

`kb.local.json` 扩展：
```json
{
  "vault": "E:\\AiknowledgeBase\\knowledgeBase",
  "depositRoot": "E:\\AiknowledgeBase\\knowledgeBase\\AI工作台沉淀内容"
}
```

## 3. 三级目录结构

```
AI工作台沉淀内容/
├─ <模块名>/            ← 第一级：工作台模块名（与侧边栏一致，去空格）
│  ├─ <YYYY-MM-DD>/     ← 第二级：日期
│  │  ├─ <内容文件>.md   ← 第三级：具体内容
│  │  └─ ...
│  └─ ...
├─ _index.jsonl         ← 沉淀日志（追加写，见 §6）
└─ _README.md           ← 本目录说明（首次写入时自动生成）
```

### 3.1 第一级 · 模块名

模块名**须与工作台侧边栏实际模块标签一致**（去空格），只对**会产生沉淀内容**的模块建目录：

| 工作台模块（侧边栏标签） | 目录名 | 可沉淀内容类型 |
|---|---|---|
| 今日 | `今日` | 今日复盘 |
| 资讯 | `资讯` | AI 日报、每日新闻精选 |
| AI助手 | `AI助手` | 对话精华、AI 日报 |
| 会话档案 | `会话档案` | 会话存档 |
| 知识库 | `知识库` | 手写笔记 / 速记 |
| 蒸馏库 | `蒸馏库` | up 主经验卡（B站/小红书/文章蒸馏，六维拆解） |

> 不产生沉淀内容的模块（仪表盘 / 本周动态 / 能力速达 / 模型管理 / 系统状态 / Skill统计 / 课程表）不建目录。
> 模块集合随工作台演进可扩展；新增沉淀模块时在本表登记，目录名沿用对应侧边栏标签（去空格）。
> 标签含空格的（如「AI 助手」）目录名去掉空格 → `AI助手`，以满足「文件名/目录名无空格」要求。

### 3.2 第二级 · 日期

- 统一 `YYYY-MM-DD`（例 `2026-08-28`），按内容**沉淀时间**的本地日期归类。
- 当日无沉淀则不建该日期目录；删除最后一份内容时清理空日期目录（可选）。

### 3.3 第三级 · 内容文件

- Markdown 文件（`.md`），见 §4 命名规范。
- 每份内容一个文件；不把多条无关内容塞进同一文件。

---

## 4. 命名规范

### 4.1 文件名规则
- 格式：`{主题关键词}.md`，主题需**简洁明确、体现核心主题**。
- 允许字符：中文、`A-Z a-z 0-9`、连字符 `-`、下划线 `_`。
- **禁止**：空格、`/ \ : * ? " < > |` 等 Windows 非法字符、emoji。
- 长度建议 ≤ 60 字符（含扩展名）。
- 示例：
  - `今日复盘.md`
  - `对话精华-glm5.3讲解RAG原理.md`
  - `AI日报-2026-08-28.md`
  - `新闻精选-大模型开源动态.md`

### 4.2 同名冲突处理
保存时若目标路径文件已存在，**自动追加序号或时间戳**，永不覆盖：
1. 先尝试 `{主题}.md`
2. 已存在 → `{主题}-2.md`、`{主题}-3.md` …（递增序号）
3. 序号碰撞激烈（≥9）→ 回退 `{主题}-{YYYYMMDD-HHMMSS}.md`（精确到秒，几乎不会重）

最终落地的文件名会回写到 UI 提示与 `_index.jsonl`，确保用户知晓真实路径。

### 4.3 目录名规则
- 同文件名规则：无空格、无特殊字符。
- 模块目录名固定（§3.1），日期目录名固定 `YYYY-MM-DD`。

---

## 5. 文件内容格式

每份沉淀 `.md` 顶部写 YAML frontmatter，使其成为合格 Obsidian 笔记（可被知识库面板解析、可加标签、可双链）：

```markdown
---
module: AI助手
date: 2026-08-28
source: ai-chat
savedAt: 2026-08-28T00:08:50+08:00
title: 对话精华-glm5.3讲解RAG原理
tags: [AI工作台, AI助手]
---

# 对话精华-glm5.3讲解RAG原理

（正文内容）
```

字段说明：
- `module`：来源模块目录名
- `date`：沉淀日期 `YYYY-MM-DD`
- `source`：内容来源枚举 `ai-chat | ai-daily | news | review | session | note | distill`
- 蒸馏库经验卡额外 frontmatter：`platform`(bilibili|xhs|article) / `author` / `url` / `topic` / `actionable`（可复用动作列表）；其中 `platform`/`topic` 也写入 `_index.jsonl`，供「蒸馏库」视图按平台/主题筛选（读取端点 `GET /api/kb/deposits?module=蒸馏库`）
- `savedAt`：ISO8601 带时区时间戳
- `title`：与文件名主题一致
- `tags`：固定含 `AI工作台` + 模块名，便于按标签检索

正文由各模块自行组织（对话精华保留 user/assistant 轮次；复盘保留完成项+心得；新闻保留标题+摘要+链接）。

## 6. 保存动作与追溯

### 6.1 保存流程（后端 `POST /api/kb/save`）
1. 入参：`{module, source, title, body}`（module 须在 §3.1 表内，title 经 §4.1 清洗）。
2. 计算 `date = today(本地)`，`dir = depositRoot/模块/date`，不存在则建。
3. 按§4.2 解析最终文件名（序号/时间戳避冲突）。
4. 写 frontmatter + body 到文件（`encoding=utf-8`）。
5. 追加一条记录到 `_index.jsonl`（见 6.2）。
6. 返回 `{ok, path, fileName, savedAt}` 给前端，前端弹提示含完整相对路径。

### 6.2 沉淀日志 `_index.jsonl`
根目录下、追加写（每行一条 JSON，便于增量读与容错）：
```json
{"savedAt":"2026-08-28T00:08:50+08:00","module":"AI助手","date":"2026-08-28","relPath":"AI助手/2026-08-28/对话精华-glm5.3讲解RAG原理.md","fileName":"对话精华-glm5.3讲解RAG原理.md","title":"对话精华-glm5.3讲解RAG原理","source":"ai-chat","bytes":1234}
```
- 用途：完整记录每次沉淀的路径与命名，支持按模块/日期/时间检索历史，确保可追溯。
- 不删不改历史行；删除某篇笔记时仅删 `.md` 文件，日志保留（注明该篇已删可选）。

### 6.3 安全与边界
- `depositRoot` 之外的路径一律拒绝（`os.path.realpath` 校验，防穿越）。
- `module` 白名单校验（§3.1 表），防任意目录。
- `title` 清洗后若为空，回退 `未命名-{YYYYMMDD-HHMMSS}`。

## 7. 浏览与检索（复用知识库面板）

沉淀目录位于父库内，知识库接入功能（计划中）的 `/api/kb/tree`、`/api/kb/search`、双链跳转**自动覆盖**沉淀内容，无需额外开发：
- 按模块浏览：左侧树展开 `AI工作台沉淀内容/<模块>/<日期>/`。
- 按日期检索：全文检索 `/api/kb/search?q=` 命中正文；`tag:AI工作台` 命中所有沉淀笔记。
- 按标题定位：标题检索命中 frontmatter title / 文件名。
- 双链：其它笔记写 `[[对话精华-glm5.3讲解RAG原理]]` 即可链接到沉淀笔记（按文件名解析）。

`_index.jsonl` 可选提供一个 `GET /api/kb/deposits?module=&date=` 端点，按模块/日期聚合返回沉淀历史，供「沉淀历史」视图使用（可在后续迭代加）。

## 8. 与工作台各模块的衔接（前端「存进知识库」入口）

| 模块 | 入口位置 | source | 默认 title |
|---|---|---|---|
| 今日 | 复盘卡「💾 保存复盘」旁加「📥 存进知识库」 | `review` | `今日复盘` |
| 资讯 | AI 日报 / 每日新闻条目「存进知识库」 | `ai-daily` / `news` | `AI日报-{date}` / `新闻精选-{主题}` |
| AI助手 | 对话区「存进知识库」按钮（存当前对话精华） | `ai-chat` | `对话精华-{首问主题}` |
| 会话档案 | 会话条目「存进知识库」 | `session` | `会话存档-{会话名}` |
| 知识库 | 面板内「新建笔记」保存即落本方案 | `note` | 用户输入标题 |

每个入口调用统一的 `kbSave({module, source, title, body})` → `POST /api/kb/save`，成功后提示完整相对路径。
