## 1 · 版本号（SemVer，本项目语义）

本项目没有对外 API/SDK，故把 SemVer 三段落到**本项目的语义**：

| 段 | 本项目含义 | 例 |
|---|---|---|
| **MAJOR** `x.0.0` | 动到**北极星/架构级**，或**破坏用户数据/URL/存储格式** | 放弃零构建上框架；改 Obsidian 目录契约；换部署地址 |
| **MINOR** `0.x.0` | **新模块 / 新能力**（向后兼容） | 蒸馏库、今日温故卡、灵感留存 |
| **PATCH** `0.0.x` | **修 bug / 小优化**（不改能力边界） | distill onclick 修复、样式补齐 |

- 现处 **`0.x`＝仍在演进、未冻结**；哪天觉得"稳定可长期依赖"再发 `1.0.0`。
- 历史版本回填见 `CHANGELOG.md`（当前 v0.8.0）。

## 2 · Commit 规范（Conventional Commits）

格式：`<type>(<scope>): <中文简述>`

| type | 用于 | 本仓实例 |
|---|---|---|
| `feat` | 新功能/能力 | `feat(recall): 今日温故卡` |
| `fix` | 修 bug | `fix(distill): onclick 漏引号` |
| `refactor` | 重构（不改行为） | `refactor(app): ES Modules 拆分` |
| `docs` | 文档 | `docs: 知识飞轮路线图` |
| `style` | 样式/格式（不改逻辑） | `style(ui): 蒸馏库补齐样式` |
| `chore` / `build` / `ci` | 杂务/构建/CI | `ci: add Python CI` |

- scope 用模块名（`distill`/`recall`/`kb`/`ui`/`backend`…）。
- 一个 commit 只做一件事；跨主题拆多个 commit。
- 尾部带：`Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>`（AI 协作署名）。

### 2.1 · `Refs:` 回指（可选尾行）

body 末尾可加一行 `Refs: <编号>, <编号>`，把这次提交挂回它服务的**需求**或**任务**：

```
Refs: R28, W0-3
```

- `R<n>` = [`requirements/需求台账.md`](requirements/需求台账.md) 的需求编号；`W<n>-<n>` = 当期作战板 `.claude/plan/作战板-<期>.md` §③ 的任务号。
- ADR 写在标题里已成惯例（`feat(usage): …（ADR 0015）`），**不必再进 `Refs:`**。
- 为什么加：本仓 112 条提交里只有约 9 条带周次/任务号，于是「这条需求花了哪些提交」只能靠回忆。加了之后：

```bash
git log --grep="Refs: R28"          # 这条需求花了哪些提交
git log --grep="Refs:" --oneline    # 这期有多少活是排过的
```

- **可选不强制**：临时修补、纯文档订正可以不带。规则见 [`guides/项目管理-操作指南.md`](guides/项目管理-操作指南.md) §5。

## 3 · ★ "what + 思路" 落在哪（三层分工）

用户最关心的"写清每次优化什么、思路是什么"——**不堆在一处**，按详略分三层，互相链接：

| 层 | 写什么 | 详略 | 文件 |
|---|---|---|---|
| **CHANGELOG** | 这版**做了什么**（Added/Changed/Fixed）+ 一句思路 + 链接 | 简 | `CHANGELOG.md` |
| **设计文档 / ADR** | **为什么这么做、代价与取舍、被否方案** | 详 | `docs/design/*-设计.md`、`docs/design/产品-IA评审.md`、`docs/adr/*` |
| **路线图** | **往哪走**（阶段、门性、依赖） | 方向 | `docs/planning/知识飞轮-路线图.md` |

> 规则：CHANGELOG 每条改动，若思路值得留，就**链到**对应设计文档/ADR，别把长篇思路塞进 CHANGELOG。重大**不可逆决策**（单向门）单独写一条 ADR。

## 4 · 发布清单（每次"收一版"时走一遍）

1. 归拢本版改动，更新 `CHANGELOG.md`：把 `[Unreleased]` 里已完成项移到新版本号下，补 Added/Changed/Fixed + 思路链接。
2. 若动了前端资源：`/home/dev_st/iriswork/tools/anaconda/bin/python bump_version.py`（重算缓存戳；CI `--check` 是硬门禁）。资产清单由脚本自动扫描，不手写；**新增 JS/CSS 文件只需加进 `sw.js` 的 `FILES`**——漏加或引用了已删文件，`--check` 会红。
3. 跑门禁：`bump_version.py --check` ✓ + `pytest` ✓ +（改了 checkJs 边界则）`tsc --noEmit`。
4. 按主题 `git commit`（Conventional Commits）。
5. **打标签**：`git tag -a v0.x.0 -m "<一句话>" && git push origin v0.x.0`。
6. `git push origin main`。

### 4.1 · 发版节奏（2026-09-21 立）

- **每个冲刺末发一版并打 tag**——不再「日常可不打」。
- **触发信号**：`[Unreleased]` 堆了 **2 周以上**，或含 **MINOR 级新增**（新模块/新能力）。
- **起点 `v0.11.0`，不追溯补 v0.7–v0.10 的旧 tag**（收益低、易错；仓里目前只有一个历史 tag `apk-1`）。
- 缘起：CHANGELOG 曾停在 `0.10.0` / 09-03 达 **17 天**，其间有 MINOR 级新增（`/api/usage`）却无版本号，"这版有什么"退化成只能翻 git log。
