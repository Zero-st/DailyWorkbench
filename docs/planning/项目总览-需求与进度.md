## 0 · 整体需求（你的知识飞轮）

把工作台做成一个 **「输入 → 捕获 → 沉淀 → 蒸馏 → 输出 → 复盘反哺」的个人知识飞轮**：

```
每日复盘 ─┐                                            ┌─▶ 精炼到 ima 知识库
获取AI资讯 ┼─▶ 好文章/灵感/up主经验 ─▶ 沉淀本地库(Obsidian) ─┤
沉淀工作流 ┘         (捕获)          (蒸馏成经验卡/skill)   └─▶ 沉淀成 skill/工作流
     ▲                                                          │
     └──────────────────── 复盘反哺（发现缺口→定向找输入）◀────────┘
```

**你陈述的 7 项核心需求 → 现状对照：**

| # | 需求 | 状态 | 落在哪 / 缺什么 |
|---|---|---|---|
| 1 | 每日代办、复盘 | ✅ | 「今日」视图代办 + 复盘卡（`js/views/dash.js`），可一键存知识库 |
| 2 | 获取每日 AI 资讯 | ✅ | 「资讯」视图 AI 日报 + 每日新闻；`daily-ai`/`sync` 定时抓取 |
| 3 | 好文章沉淀到本地库 | 🔧 | `kbSave` 底座已通，但**缺"看到文章→一键剪藏入库"的顺手入口** |
| 4 | 提炼到 ima 知识库 | 🚧 | 零实现；ima 无写 API，走**文件交接**（`待入ima/` 手动导入）— 路线图 Phase 4 |
| 5 | 记录每日灵感 | 🔧 | 只有「给我灵感」一次性 prompt 指令，**没留存**— 路线图 Phase 2 |
| 6 | 沉淀工作流 / skill | 🔧 | 「能力速达」能查/启动已装 skill，但**"把重复劳动固化成 skill"的捕获流没有** |
| 7 | 蒸馏小红书/B站 up 主经验 | ✅ | 「蒸馏库」视图（`js/views/distill.js`）：链接→skill 萃取→六维经验卡→落 Obsidian `蒸馏库/`，可筛选/检索。Phase 1 已完成 |
| ✚ | 持久化 / 多端 / 上云 | 🚧 | 用户内容散在 localStorage（不跨端）— 路线图 Phase 2-4 |

## 1 · ✅ 已完成（可用）

### 1.1 前端 PWA · 6 个功能视图（v0.8.0 MVP 聚焦后，按知识飞轮排列）

分组：**今日** ｜ **飞轮**(资讯·知识库·蒸馏库·AI助手) ｜ **设置**(模型管理)。MVP 只留飞轮主轴 + AI 配置。

| 分组 | 视图 | 说明 |
|---|---|---|
| 今日 | `home` | 捕获+复盘中枢：代办 + 复盘 + 温故卡 + 速记/收藏/常用入口/快捷启动（原仪表盘交互件已并入） |
| 飞轮·输入 | 资讯 `info` | AI 日报 + 每日新闻（分栏） |
| 飞轮·沉淀 | 知识库 `kb` | Obsidian vault 浏览 / 检索 / 双链 / 沉淀 + 新建笔记/蒸馏/搜索动作 |
| 飞轮·蒸馏 | 蒸馏库 `distill` | up 主经验卡：链接→六维萃取→落 Obsidian `蒸馏库/` |
| 飞轮·输出 | AI 助手 `ai` | 大白话问答，可「存知识库」对话精华 |
| 设置 | 模型管理 `models` | AI 平台与模型配置（Supabase 云端 / localStorage 兜底） |

> **MVP 从导航下架（代码/数据全保留，加回按钮即恢复）**：能力速达 `cap`、动态 `sess`、系统状态 `ov`——三者均属「看机器」遥测/工具，不推动飞轮流动。
> 更早已下线：仪表盘（拆解分发·v0.7.0）、Skill 统计（→cap·v0.7.0）、本周动态（→sess·v0.7.0）、课程表（离题·v0.7.0）——代码同样保留。

**通用体验**：深色/浅色主题、桌面自适应（宽窗双栏/窄窗单列）、离线可开（Service Worker）、离线提示条、防白屏（`normalizeData` 兜底 + `render` try/catch）。

### 1.2 后端本地服务（`backend/server.py`，stdlib 零依赖）
8 条 API：`GET /api/{models, kb/tree, kb/note, kb/search}`、`POST /api/{chat, models, kb/save, refresh}`。只绑 `127.0.0.1`。

### 1.3 沉淀 · 知识库（写入侧全链路已通）
`/api/kb/save` → Obsidian 三级目录（模块/日期/内容）+ `_index.jsonl` 追溯日志，规范见 `知识库沉淀存储方案.md`。已接入口：AI 助手对话精华、今日复盘。

### 1.4 数据流水线 · 自动化
- `export_data` 从本机 WorkBuddy 抓真实数据 → `data.json`（KPI/Skills/自动化/模型/记忆/引导）。
- `fetch_ai_daily` / `fetch_daily_news` / `daily_ai` 抓资讯。
- 4 个 GitHub workflow：`ci`（质量门禁）、`deploy-pages`、`sync`（每小时自助 runner）、`daily-ai`（每日 08:30）。

### 1.5 交付形态（PC-first）
纯静态本地、本地全功能后端、GitHub Pages 在线版（固定址）、PWA 安装（桌面/手机浏览器）、lite 纯静态版。**原生/APK 移动端（Flutter `mobile/`、TWA `twa/`）已于 v0.9.0 下线**（PC-first，见 `../adr/0005-pc-first-drop-native-mobile.md`）。

### 1.6 工程护栏 & 治理（近期重构成果）
- `bump_version.py` 内容 hash 缓存戳自动同步（CI 硬门禁）。
- 真门禁 CI：flake8 + pytest + `tsc --noEmit`（JSDoc/checkJs 覆盖 state/net 边界）。
- 后端收敛为分层 package（`backend/{core,utils,clients,pipeline}`）。
- 前端资源分类（css/js/vendor/icons）、脚本归 `scripts/`。
- 治理文档：`TECH_CHARTER.md` + 4 条 ADR + `知识飞轮-路线图.md` + `界面设计准则.md` + `产品-IA评审.md` + `CHANGELOG.md` + `版本管理规范.md` + 本总览。
- README 重写为分平台部署手册。

| 阶段 | 内容 | 代价 / 门 |
|---|---|---|
| ~~**Phase 1**~~ ✅ | ~~**up 主经验蒸馏库**（结构化经验卡 → Obsidian `蒸馏库/`，纯本地）~~ **已完成 2026-08-31** | 低 · 双向门 |
| **Phase 2** | 每日灵感留存 + Obsidian 库 git 备份 | 低-中 · 双向门 |
| **Phase 3** | 云端薄收件箱（Supabase `capture_inbox`）+ 多端实时同步 + PC 抽干归库 | 中 · **含单向门→先写 ADR** |
| **Phase 4** | 手机全功能 + 出口闭环（一键归拢 `待入ima/`）+ 复盘反哺聚合 | 中-高 · 较大门 · 压轴 |

**关键约束（来自路线图/宪章）**
- 云只当"跨设备暂存收件箱"，**不当主库**；不把 Obsidian 整库搬上云。
- ima **不做 API 集成**，纯文件交接、手动导入。
- 除已认证的 Supabase 外，**不引新中间件**（YAGNI）。
