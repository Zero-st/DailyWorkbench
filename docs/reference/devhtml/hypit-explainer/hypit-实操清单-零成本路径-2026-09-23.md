# Hypit 实操清单 · 零成本路径（第一次跑通）

> 配套图解：`hypit-小白图解-2026-09-23.html`（同目录）。
> 取材日期 2026-09-23，对应 Hypit v0.2.12。这个项目 8 天发了 20 个版本，**命令若与你看到的不一致，以 `https://github.com/hypit-ai/hypit` 当前 README 为准**。

## 先说清「零成本」是什么意思

| 环节 | 花不花钱 | 依据 |
|---|---|---|
| Hypit 软件 | 免费，不加水印，不按渲染次数收费 | README.zh-CN.md §只安装一次、§为什么选择 Hypit |
| 渲染成片（在你电脑上跑） | 免费 | docs/zh/guide/develop.md §前置条件 |
| 生成模型（AI 生图 / 生视频 / 配音） | **本清单全程不用**，所以 0 元 | README §Hypit 第 53 行：「字幕、动效和代码渲染的画面，不调用生成模型也能编译成一条成片，因此可以不产生模型服务费用」 |
| Coding Agent（Claude Code 或 Codex） | **要账号，通常要钱**；Hypit 文档只说「各有自己的账号与费用」，没给价格 → **原文未说明** | README §只安装一次；docs/zh/quickstart.md §1 |

所以：**「零成本」= 零模型费 + 零软件费。AI 助手的费用另算。** 如果你已经有 Claude Code 或 Codex 账号，本清单从头到尾不再多花一分钱。
不用 AI 助手、纯手敲命令的新手路径，原文没有提供（仓库里的示例要求克隆仓库和开发环境）→ **原文未说明**，本清单不走那条路。

## 你需要先有的东西

| 东西 | 干什么用 | 怎么确认有了 | 依据 |
|---|---|---|---|
| 一台 Mac 或 Windows 电脑，能上网 | 装工具、下载 Chromium | — | docs/zh/guide/develop.md（Chromium 由 `hypit runtime up` 下载）；local-tools.md 给了 macOS / Windows 两套安装命令 |
| Node.js **22.15 或更高** | 运行 `npx` 和 `hypit` 命令的底层 | 见步骤 0 | README 顶部徽章「Node.js 22.15+」；develop.md §前置条件 |
| Claude Code 或 Codex（任一） | 你唠嗑的对象，它替你敲后面的命令 | 能在终端里启动它并对话 | docs/zh/quickstart.md §你需要准备：「支持 Skill 的 Coding Agent，例如 Claude Code 或 Codex」 |
| 一句话描述你想要的视频 | 不用参考视频也行 | — | README §使用 Hypit skill：「也可以不提供参考视频，直接从描述开始」 |

**术语**：
- **终端 / 命令行**：Mac 上叫「终端」，Windows 上叫「PowerShell」。一个黑框，你打字、它回话。
- **Node.js**：让这类命令行程序能跑起来的底层环境，从 nodejs.org 下载安装包，一路「下一步」。
- **Coding Agent / AI 编程助手**：能在你电脑上读写文件、执行命令的 AI 程序。Claude Code 是 Anthropic 的，Codex 是 OpenAI 的。它们的安装方法不在 Hypit 文档里 → **原文未说明**，请看各自官网。

## 步骤 0 · 确认底子（自己敲）

**敲什么**（这行不是 README 原句，是通用核对命令）：

```bash
node -v
```

- `node` = 叫出 Node.js；`-v` = 「报一下版本号」。

**该看到什么**：一行 `v22.15.0` 或更大的数字（比如 `v22.19.1`、`v24.x`）。

**看到别的说明哪里错了**：
- `command not found` / `不是内部或外部命令` → Node.js 没装，或装完没重开终端。装完**关掉终端重开**再试。
- `v18.x`、`v20.x` 这种小于 22.15 的 → 版本太低，去 nodejs.org 装新的（README 徽章明写 22.15+）。

然后启动你的 AI 助手，确认能对话。这一步的具体操作以助手官网为准。

## 步骤 1 · 装 Hypit 技能（自己敲，全程唯一一条）

**敲什么**（README.zh-CN.md §只安装一次 原句）：

```bash
npx skills add hypit-ai/hypit -g
```

逐段讲：
- `npx` = 临时下载并运行一个小工具，用完不留。
- `skills add` = 用那个小工具「添加一个技能」。**技能（Skill）**= 一份给 AI 助手看的说明书，装了它助手就知道怎么用 Hypit。
- `hypit-ai/hypit` = 技能来自 GitHub 上这个仓库。
- `-g` = global，装成「全局」的，以后在哪个文件夹里开助手都能用。

**该看到什么**：安装过程的输出，最后没有红色 error。原文没有给出具体的成功提示文字 → **原文未说明**。想核对就再敲一条（来自 skills/hypit/references/environment/distribution.md）：

```bash
npx skills list -g
```

列表里应出现 `hypit`。

**看到别的说明哪里错了**：
- `npx: command not found` → 回步骤 0，Node.js 没装好。
- 长时间卡住 / `ETIMEDOUT` / `network` 字样 → 网络到不了 GitHub 或 npm。换网络或稍后再试。
- 提示要装 `skills` 包、问 `Ok to proceed? (y)` → 正常，按 `y` 回车。

**注意**：这一步**只装了说明书，没装 Hypit 程序本身**。文档原话：「首次使用时，Agent 会检查 Hypit 可执行程序，并按需协助安装」（README §只安装一次）。程序在步骤 3 由助手装。

## 步骤 2 · 开一个空文件夹，在里面启动助手

**做什么**：在桌面新建一个空文件夹（比如叫 `my-first-video`），在终端里进到这个文件夹，再启动 Claude Code 或 Codex。

依据：README §使用 Hypit skill：「在任意空目录或现有项目目录中开启会话」。

**该看到什么**：助手的对话提示符。

**看到别的说明哪里错了**：
- 助手启动了但你不确定它在哪个文件夹 → 直接问它「你现在在哪个目录」。
- 在一个塞满别的东西的文件夹里开 → 不算错，但新手建议用空文件夹，免得助手误读别的文件。

## 步骤 3 · 开口说（对助手说话，不是敲命令）

**说什么**，两段话，第一段是 README §使用 Hypit skill 的原句，第二段是**我拟的约束**（不是 README 原句，依据 README §Hypit 第 53 行和 quickstart §4）：

```text
/hypit 做一个 ranking 视频，把 Hypit 排到 S 级。
```

```text
约束：这次只用代码渲染的画面和字幕，不调用任何付费生成模型（不生图、不生视频、不合成语音、不用托管 WhisperX）。任何需要账号、密钥或会产生费用的步骤，先停下来问我。
```

- `/hypit` = 呼出刚装的技能；后面那句是你的需求。
- 「ranking 视频」= 排行榜视频（把几样东西分 S/A/B/C/D 级那种）。
- 为什么加约束：README 说「Agent 会检查环境，索要这条视频需要的凭据，生成素材并构建成片」——不加约束它可能默认走生成模型路线，那就要钱了。

**该看到什么**（依据 README §只安装一次、quickstart §1）：
1. 助手说它在检查环境，发现 `hypit` 程序没装，**提出要装**。文档给的安装命令是（distribution.md §Install the executable package）：
   ```bash
   npm install --global @hypit/hypit
   ```
   - `npm install` = 安装一个软件包；`--global` = 装成全局命令；`@hypit/hypit` = Hypit 的正式发行包名。
   → **同意**。这是免费的。
2. 装完它可能跑 `hypit version` 核对（distribution.md §Find the installation already available）。**该看到**：打印出版本号（取材当天是 `0.2.12`）。
3. 它可能说需要 `ffmpeg` / `ffprobe`（处理音视频的通用工具，免费开源）。文档给的命令（local-tools.md §Supply host executables at machine scope）：
   - macOS：`brew install ffmpeg`
   - Windows：`winget install --id Gyan.FFmpeg.Shared -e`
   → **同意**。
4. 它会说要准备渲染用的浏览器（Chromium），命令形如 `hypit runtime up`（develop.md §前置条件：「Chrome / Chromium 由 hypit runtime up 下载」）→ **同意**，这一步要下载几百 MB，等一会儿。
5. 然后它开始写「菜谱文件」（`.svml` / `.svs` / `.svrun`），并且**应该说明**它打算怎么做这条视频。

**看到别的说明哪里错了**：
- 助手说「没找到 /hypit 技能」→ 步骤 1 没装成功，或装到了另一个用户/另一台机器。回步骤 1 用 `npx skills list -g` 核对。
- 助手问你要 **HypiHub 账号 / 登录 / API Key** → 它准备用付费服务了。回答：「不用，这次只做代码渲染和字幕，不需要任何外部服务。」（依据 README §Hypit 第 53 行）
- 助手问要不要装 **WhisperX**、要装 **Python / uv** → 这是「听词对齐」用的，只有**有人说话的参考视频**才需要（quickstart §3）。这次没有参考视频、不合成语音，回答「不需要」。
- 助手说要 `brew` 但你 Mac 上没有 Homebrew → 让它先告诉你怎么装 Homebrew，或者让它换一种安装 ffmpeg 的方式。
- `npm install --global` 报 `EACCES` / 权限错误 → 让助手换成不需要管理员权限的安装方式；不要盲目加 `sudo`。

## 步骤 4 · 看账单，再点头（助手敲，你看）

助手写完菜谱文件后，**应该**先跑「算账」而不是直接开工。文档原话：「只有 `build` 会真正提交工作。`plan` 展示选中的工作」（run.md）；「付费工作开始前，Agent 会说明使用哪个账户、准备做什么、可用费率或预计费用」（quickstart §4）。

助手会跑的命令形如（run.md §日常制作 / §查询所选 Run 的费用信息；文件名以助手实际起的为准）：

```bash
hypit plan build.svrun
hypit pricing build.svrun
```

- `plan` = 「列出这次要做哪些事、用哪些服务」，不花钱、不动手。
- `pricing` = 「这些事里哪些要付费、费率多少」。文档说会把「明确声明为本地无 Provider 调用费用的工作汇总显示」。

**该看到什么**：
- `plan` 里列出的都是本地渲染、字幕、混音这类本地工作；
- `pricing` 里**没有任何付费请求**，或者明确显示「本地、无调用费用」。

**看到别的说明哪里错了**：
- `pricing` 里出现 Seedance / GPT Image / Fish Audio / HypiHub 等模型名或带价格的条目 → 助手把生成模型写进菜谱了。对它说：「把所有生成模型请求去掉，改成代码渲染的画面。」（依据 README §Hypit 能构建什么：「代码渲染的视频 —— 画面完全由前端代码驱动，本地渲染，无需调用生成模型 API」）
- `plan` 报「缺少凭据」→ 同上，说明菜谱里有需要账号的服务，让助手去掉。
- 助手跳过 plan 直接 build → 不算大错（这次本来就 0 元），但下次要花钱时这个习惯很危险。可以提醒它「以后付费前先 plan 给我看」。

## 步骤 5 · 出片（助手敲，你等）

助手会跑（run.md §日常制作 原句，文件名以实际为准）：

```bash
hypit build build.svrun --follow
```

- `build` = 「真正开工」，是唯一会动手（也是唯一可能花钱）的命令。
- `--follow` = 「把进度实时打在屏幕上」。文档说不带它 build 会转到后台继续。

**该看到什么**：
- 进度一行行往下刷（phase / Operation 数量变化，run.md §--follow）；
- 结束时，文档说「Build 的最终输出会为每个文件 Target 打印精确的 `get --output …` 命令」（run.md 第 409 行）。助手接着跑那条命令，形如：
  ```bash
  hypit get <build-id> --output final.video --to output/final.mp4
  ```
  - `get` = 「把结果取出来」；`<build-id>` = 这次 build 的编号（屏幕上打印的那串）；`--output final.video` = 要哪个产物；`--to output/final.mp4` = 存到哪、叫什么。
- 文件夹里出现 `output/final.mp4`。**双击能播，有画面、有字幕，就是跑通了。**

**看到别的说明哪里错了**：
- 报 `ffmpeg` / `ffprobe` not found → 步骤 3 第 3 条没装好或没生效。**关掉终端重开**（local-tools.md：「新的 PATH 设置必须到达运行工作的进程；只重启终端不会改变已存在的 Worker」→ 所以还要让助手跑 `hypit runtime down` 再 `hypit runtime up`）。
- 报浏览器 / Chromium 相关错误 → 让助手跑 `hypit runtime up`（develop.md）重新准备。
- 报「缺少凭据」/ 要登录 → 菜谱里混进了付费服务，回步骤 4。
- 卡住很久不动 → 让助手跑 `hypit runtime logs`（run.md §7）看日志，或 `hypit doctor`（run.md：「doctor 用于配置和排查部署」，只诊断不花钱）。
- 按了 Ctrl-C → 文档说「Ctrl-C 不会取消任务」，后台还在跑；用 `hypit runtime down` 才是停。

## 步骤 6 · 可选 · 在浏览器里看时间线

助手可以跑（docs/zh/quickstart/preview.md 原句）：

```bash
hypit studio --run build.svrun
```

- `studio` = 打开 Hypit 自带的看片页面；`--run` = 看哪份「本次做什么」文件。

**该看到什么**：终端打印一个网址（默认端口 5179），浏览器打开后能播放、逐帧看、在时间线上点到每个词。左上有地球图标可切中文界面。

**看到别的说明哪里错了**：
- 网址打不开 → 端口被占。让助手加 `--port 5180` 换一个（preview.md 参数表）。
- 你在远程机器上跑（比如助手在云端）→ 文档明说「远程机器的 localhost 地址，并不是你电脑上的预览地址」（agents.md），得让助手把 mp4 文件交给你，或做端口转发。

## 跑通之后：下一步要花钱的地方

想真正「克隆一条爆款」而不是做一条排行榜，会多出两处开支（都在 quickstart §3、§4）：

1. **听词对齐 WhisperX**：参考视频里有人说话，就得让机器听出每个字在哪一刻。两条路：本机装（免费，但要 Python 3.10～3.13 + uv，还要下载模型，体积与耗时**原文未说明**）；或用托管 HypiHub（收费，价格**原文未说明**，可用 `hypit pricing` 查）。
2. **生成模型**：要 AI 演员、AI 配音、AI 配图，就要按次付外部服务的钱。README 三个示例自称每条约 $1.07～1.15（**项目自称**，未独立验证）。

无论哪条，助手都应该先跑 `plan` / `pricing` 报价，你点头它才 `build`。**没点头它就花了钱，这是它的错，不是你的。**

## 一页排查表

| 症状 | 最可能的原因 | 回到哪一步 |
|---|---|---|
| `command not found: npx` | Node.js 没装 / 没重开终端 | 步骤 0 |
| 助手不认识 `/hypit` | 技能没装上 | 步骤 1，`npx skills list -g` |
| 助手要 API Key / 让你登录 | 它走了付费路线 | 步骤 3，重申约束 |
| `pricing` 里有价格 | 菜谱含生成模型 | 步骤 4，让它改代码渲染 |
| `ffmpeg not found` | 工具没装 / PATH 没生效 | 步骤 3 第 3 条，重开终端 + `runtime down/up` |
| Chromium 报错 | 浏览器没准备 | `hypit runtime up` |
| 卡住不动 | 看日志 | `hypit runtime logs` / `hypit doctor` |
| 没有 `output/final.mp4` | 没跑 `get --output` | 步骤 5，照屏幕上打印的那条命令跑 |
