# 0005 PC-first：暂弃原生/APK 移动端交付，聚焦桌面 Web
- 背景：一人维护的项目此前并行 6 种形态（纯静态/本地后端/GitHub Pages/手机PWA/安卓APK[TWA+Flutter]/lite），移动端交付（`mobile/` Flutter、`twa/` TWA、`app-data.json` 云备份、`build-apk` 工作流/脚本）从未成为主用路径，却持续占维护面（宪章卡：一人长期并行多套 UI 最贵）；且飞轮功能尚未成型。
- 决策：**先把 PC 端做扎实，功能成型后再回头做移动端**。删除原生+APK 两条移动交付及其构建产物/工作流/脚本；**保留** PWA manifest/SW（桌面 PWA + 离线）与 `lite/`（独立轻量分叉，零维护耦合）。
- 理由：把维护力集中到唯一在用的桌面 Web + 后端；移动端在飞轮核心（捕获→蒸馏→复用）稳定前投入是过早优化（YAGNI）；PWA 已能覆盖"装到桌面/离线"的现实需求。
- 代价：移动端来日需重做（但 git 历史可回捞 `mobile/`/`twa/`；数据契约 `data.json`/`/api/*` 未变，重接成本可控）；GitHub Pages 上 `/lite/` 保留、`/mobile|twa` 子路径消失。何时重估——桌面飞轮功能成型、且出现真实"手机随时捕获/查阅"高频诉求时（届时优先经云收件箱中转，而非重起原生 App）。
