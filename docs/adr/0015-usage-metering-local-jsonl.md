# 0015 使用量埋点：独立本地 jsonl，不进 data.json

- 状态：已接受
- 日期：2026-09-20
- 关联：[ADR 0013](0013-drop-workbuddy-telemetry.md)（刚切除的遥测线，其「何时重估」正指向本篇）、[ADR 0006](0006-capture-layer-browser-extension.md)（inbox.local.json 的先例）、`docs/guides/项目自评打分-指南.md`、`docs/planning/复盘-项目自评打分-2026-09.md`

## 背景

2026-09-17 的自评卡总分 **0**——硬门·频率门不过：17 天里只有 3 天有使用痕迹，最近 6 天为 0。同一张卡还记下：R01 每日复盘 / R11 今日温故卡 / R12 捕获收件箱三条已标 ✅ 的需求，**实测使用量全是 0**。

问题不止于"没被用"，更在于**量不动**：当时的取数方式是用 chrome-devtools MCP 连调试 Chrome、再用 `ldbdump` 解析 LevelDB 里的 `localStorage`，1~2 小时一次，还要先决定"以哪个 profile 为准"，且调试 Chrome 常年 LA 时区会让 `wb_review_<date>` 的日期错一天。心法 §4 说"默认第 1 档起步，绝不跳档"——量测这件事的第 1 档（手工填表）已经跑过一次：`docs/planning/复盘-dogfood冲刺-W1.md` 的 7 行表 **0/7 回填**。这是升档的实证依据，不是跳档。

## 决策

**新增一条本地埋点线：前端 `POST /api/usage` → 仓库根 `usage.local.jsonl`（append-only），配一个只读 CLI 报表。`data.json` 一个键都不加。**

- 行格式：`{"at","day","ev","cid","k?"}` 五个键，服务端白名单裁剪，多余键一律丢弃。
- `day` 由**服务端**按本机时区盖戳，不信前端时区。
- `cid`：前端随机 8 位 hex 存 localStorage。它**替代了自评卡 §5 第 0 条**（"先固定用哪个 profile"）——任何 profile 打开 127.0.0.1 都上报到同一个后端，`cid` 天然把设备分开又能合计。
- 事件白名单见 `backend/clients/usage.py` 的 `EVENTS`。**明确不采集**页面加载、视图切换、30s 轮询、渲染次数——那是"开着标签页"不是"在用"，采了就是自评指南 §9 点名的 vanity metrics。
- 消费者**不是视图，是 CLI 报表 + 自评卡**（`python -m backend.pipeline.usage_report`）。

## 理由

- **为什么不进 `data.json`**：那是前端契约、是单向门（`TECH_CHARTER` 的单向门清单），且 ADR 0013 刚把它从 17 键收窄到 9 键。往回加键会与那次决策正面冲突。独立文件完全规避。
- **为什么不是继续读 localStorage**：见背景——已被证明量不动，且它只有"最后一次状态"没有次数。
- **为什么不做"使用统计"视图**：三重撞线——① 指南 §9 的 vanity + 一人项目自恋；② ADR 0013 刚砍掉的正是"看机器在干嘛"的视图；③ 它会让人**看统计代替用工具**。
- **为什么真卡/收件箱/同步不走埋点而读磁盘**：前端自报的数字可以被"我点一下"刷出来，磁盘产物不能。报表因此四源交叉。

## 代价 / 护栏 / 何时重估

- **单向门**：`usage.local.jsonl` 的行格式。已经写下的行改不回去；改 `EVENTS` 或字段要回本篇记一笔。端点与前端模块本身是双向门（删了就没了）。
- **隐私红线**：行里**没有任何自由文本字段**。复盘正文、速记内容、捕获 URL 一律不进；`k` 只对 `recall_*`/`kb_*`/`distill_*` 生效且只存 vault 相对路径。测试 `test_usage_drops_free_text_fields` 是这条红线的回归钉。
- **不得被外部灌数**：`/api/usage` 必须过 `_guard_origin()`。否则任意网页都能往日志里灌，这份数据就不能用来回答"我到底有没有在用"了。
- **泄露面**：`deploy-pages.yml` 把**整个仓库**（`path: .`）发布成公开 Pages，故 `usage.local.jsonl` 必须在 `.gitignore` 里（已加，文件名带 `.local.` 沿用 `inbox.local.json` 先例）。
- **证据边界（自评时必须写进卡里）**：只有从 `http://127.0.0.1:<port>` 打开的会话会被计量。GitHub Pages 版测不到——https 页面不允许向 http 本地端口发请求。因此日常入口＝本地，Pages 只当离线备份视图。
- **优雅劣化**：后端不在时前端 fetch 直接失败、静默丢弃，绝不阻塞任何交互；不做离线队列（丢一条使用记录无所谓，队列是多一份要维护的状态）。
- **放弃线（尺子自己也受同一把尺子约束）**：到 2026-10-17 对表时，若报表的 `report_run` 少于 4 次，说明这把尺子自己没被用——**删掉 `/api/usage`、`usage.local.jsonl`、`js/core/usage.js`，本篇标「已废弃」**。
- **何时重估**：若哪天真需要在页面上看使用量，先回头读 ADR 0013 的教训（消费视图先于数据线），不要因为"数据都在了"就顺手加一个视图。
