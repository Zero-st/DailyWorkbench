# 0016 工作台内「项目进度」视图：读作战板 markdown，只开两处写

- 状态：已接受
- 日期：2026-09-21
- 关联：[ADR 0015](0015-usage-metering-local-jsonl.md)（**本篇修订它「不做使用统计视图」那条**，并扩 `EVENTS`）、[ADR 0013](0013-drop-workbuddy-telemetry.md)（切除遥测线，其「何时重估」要求"消费视图先于数据线"）、[`../guides/项目管理-操作指南.md`](../guides/项目管理-操作指南.md)（DoD 四款与换期清单）、`R29`/`R30`

## 背景

2026-09-21 建的执行层（作战板 + 指南 + `usage_report --mix`）把完成度变成可计算的了，但三个数字分散在三处、靠人手算手抄：当期门禁 2/6（作战板）、需求 16/23（台账 §4）、周门（周表）。用户要求「在工作台里看到进度 + 两层计划表」。

这件事**正面撞上 ADR 0015 写死的三条理由**（不做使用统计视图：① 指南 §9 的 vanity + 一人项目自恋；② ADR 0013 刚砍的正是"看机器在干嘛"的视图；③ 它会让人看统计代替用工具），也撞上对表冲刺负向清单的「给 dogfood 做完成度仪表 = 活动剧场」。用户在看过全部代价后拍板要做，故本篇逐条回应。

## 决策

**新增只读为主的「项目进度」视图：数据全部从既有 markdown 派生，页面上零手打数字；写侧只开 §⑤ 偏离追加与 §④ 风险状态两处。**

- 读：`GET /api/progress` ← `backend/clients/progress.py` 解析 ① 作战板 §⓪ 两层计划表 / §② 勾选框 / §④ / §⑤ ② 需求台账 §4 汇总 ③ 作战板头部声明的周表 ④ `usage_report.metrics()` 与 git log。
- 写：`POST /api/progress/{deviation,risk}`。**`data.json` 一个键都不加**（单向门，且 ADR 0013 刚把它 17→9 键）。
- `EVENTS` 增 `progress_open`（改 `EVENTS` 是单向门，ADR 0015 要求回记一笔——就是这里）。只在**明确手势**切到该视图时记，恢复上次标签不算。

## 理由：逐条回应 ADR 0015 的三条

**① vanity / 自恋** — 页面置顶不是成就，是**判决条**：距对表日 N 天 + 当前几条放弃线正踩线 + 触发后要执行什么动作（首次真机实测：26 天 / 4 条踩线 / 含"整个前端进删除测试"）。看它不会让人自我感觉良好。

**② 撞 ADR 0013 砍掉的"看机器"视图** — 那三个（`ov`/`cap`/`sess`）看的是**机器在干嘛**（磁盘、已装 skill、会话），与人的判断无关，删时一点不心疼。本视图看的是**自己离放弃线还有多远**，直接服务 10-17 那次判决。两者对象不同：前者是消遣，后者是压力。

**③ 看统计代替用工具** — 这条**承认有风险且无法先验排除**，所以给它装了自己的尺子与放弃线（见下）。若 10-17 时 `progress_open < 4`，说明它连被看都没有，删掉；若它被频繁看却使用量仍不涨，那正是第 ③ 条应验，也照删。

**兑现 ADR 0013 的「消费视图先于数据线」**：本次顺序是先定视图形态与判决条内容，再决定读哪几处 markdown，且**没有新建任何数据源**——不复活旧遥测线的形状，只读已经存在、人本来就在维护的文件。

**为什么读 markdown 而不是新建结构化数据**：本仓已有三个"手工维护的第二份数据必然漂移"的实证——`路线图全景与决策看板.html`（硬编码、14 天未动、三条 Next/Later 里两条与现状相反）、`产品评分卡-v0.8.0.html`（已退役）、`项目总览` §1.1（至今写着早已删除的视图"代码全保留"）。真源只留一份：人写的那几张表。

## 写侧边界（为什么只开两处）

| 位置 | 开不开 | 理由 |
|---|---|---|
| §⑤ 偏离记录追加 | ✅ | 无 DoD 约束，纯记录。**开编辑器记一行的摩擦，正是它不会被记的原因** |
| §④ 风险状态 | ✅ | 同上，白名单五态，只改一格 |
| §②③ 勾选 `[x]` | ❌ | 指南 §3 要求勾前过 DoD 四款（已 commit·跑过门禁·**写一句可验证的验收事实**·台账已回写）。一键勾选把四款架空，而「计划宣称完成、无人逐条对过」正是这套机制要治的病——W0 宣称做完实测 2/6 就是 09-21 抓到的 |
| §⓪① 计划表与基线 | ❌ | 基线期中不该改；给了入口就会改。要改走 §⑥ 记变更 |

`test_progress_writes_never_touch_checkboxes` 锁的就是这条边界（不变量断言，非命名检查）。

## 代价 / 护栏 / 何时重估

- **这是本应用第一次写 git 跟踪的文件**（此前写盘全在 Obsidian vault 与 `*.local.json`）。护栏四条：**外科手术式改行**（只动目标行，绝不重新生成文件——重生成会毁掉人写的注释与散文；实测 `git diff` 为 `1 insertion(+)`）、**内容哈希前置条件**（页面加载后文件被改过 → 409 拒绝并回传当前 hash，宁可拒绝也不覆盖）、**单元格转义**（`|` → `\|`、换行压空格、长度封顶 200，否则撑坏表格）、**原子写** `tmp + os.replace`。两个端点都过 `_guard_origin`。
- **markdown 解析脆**：表头即契约。对不上时**返回 `None` + note、绝不猜、绝不静默填 0**，页面顶部自曝「某段解析失败」；CI 有 `test_progress_parses_the_current_real_board` 直接解析真实当期作战板，改坏表头 `pytest` 就红。
- **不写死期号**：对表日与周表路径都从作战板头部读（曾写死 `2026-10-17` 与周表文件名，换期即烂）；`board_path()` 只认 `作战板-\d{4}-\d{2}.md`，模板与归档天然排除。换期＝新建一张板，代码一行不改。
- **深色态不可读**：`.pg-*` 继承全站已知缺陷 **D2**（`:root` 的 `--ink`/`--ink-strong`/`--sub` 系仍是浅色值，实测正文 1.31:1）。**非本批引入**，已排期 W3 门禁补课（硬截止 10-15）。用户日常用浅色。
- **侧边栏 6 → 7 项**，逆 R10「别让我想我该点哪个」的收敛方向。新开「项目」组一项；若被放弃线删掉，导航位一并收回。
- **过不了心法 §4 频率门**（一个进度页大概率 < 2 次/周）。缓解是今日页一行摘要，让它**来找你**而不是你去找它。这个缓解有没有效，10-17 由 `progress_open` 回答。

### 放弃线（预注册，2026-10-17 与冲刺同日执行）

| 指标 | 线 | 动作 |
|---|---|---|
| `progress_open`（30 天） | **< 4 次** | 删视图 + 两个写端点 + `progress.py` + `.pg-*` CSS + 侧栏项，本篇标「已废弃」，计划总表退回纯 markdown |
| 页面数字与真源不一致 | 出现任意 1 次 | 解析脆了 → 要么修，要么退回 CLI 报表 |
| 看它却不用工具（§ 理由 ③ 应验） | 10-17 时 `progress_open` 高而 `usedDays` 仍 < 8 | 同样删——它成了看统计代替用工具的载体 |

**尺子自己也受同一把尺子约束**，与 ADR 0015 同例。

## 被否方案

- **CLI 报表加一段「项目进度」**（最省、零撞线，且符合 ADR 0015「消费者是 CLI 报表」）：否掉的理由是用户明确要在产品里看，且今日页摘要行需要一个前端落点。**若放弃线触发，退回的就是这个方案。**
- **生成一张 HTML 看板放 `docs/reference/devhtml/`**：有先例，但那个先例正是烂掉的那张（14 天未更新、内容与现状相反）——离线快照必然漂移。
- **新建结构化数据文件（JSON）当真源**：会制造第二份要人维护的数据，正是本仓反复踩的坑。
- **页面开放勾选 `[x]`**：见「写侧边界」。回头条件＝想清楚怎么在 UI 上**强制**填写「一句可验证的验收事实」并跑过门禁，届时回本篇修订。
