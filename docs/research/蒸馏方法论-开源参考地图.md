## 1 · 头号参考 · danielmiessler/fabric

[github.com/danielmiessler/fabric](https://github.com/danielmiessler/fabric) —— 开源提示词框架，140+ 个可复用 **pattern**（每个就是一个 `system.md`）。它把「提取什么 / 怎么评价」几乎做成了现成答案。**最值得抄的不是某段文字，是它「每段规定几条、每条几个词」的强约束工艺**——这正是我们六维模板缺的那一层。

### 相关 pattern 的实际输出骨架（可直接抄）

- **`extract_wisdom`**（核心）— 固定 9 段，每段带硬性数量/字数：
  - `SUMMARY` — 25 词以内（谁讲了什么）
  - `IDEAS` — 20~50 条（至少 25），每条正好 16 词
  - `INSIGHTS` — 10~20 条，每条 16 词（IDEAS 里最好那批的再提炼）
  - `QUOTES` — 15~30 条，原文 + 出处
  - `HABITS` — 15~30 条，可操作的习惯/做法
  - `FACTS` — 15~30 条，关于世界的意外事实
  - `REFERENCES` — 提到的书/工具/作品
  - `ONE-SENTENCE TAKEAWAY` — 正好 15 词的核心一句
  - `RECOMMENDATIONS` — 15~30 条可执行建议
  - 格式硬规则：只输出 Markdown、只用无序列表、段间不重复、同段不重复开头词、不加任何说明/警告
- **`rate_content` / `label_and_rate`** — 现成的「值不值得存」打分器（详见 §3-②）
- **`summarize` / `create_summary`** — 20 词一句 + 主要点（≤16 词/条）+ 关键 takeaway
- **`summarize_micro` / `create_micro_summary`** — 极简版（3 点 3 takeaway），适合**卡片级**蒸馏
- **`extract_insights`**（16 词/条）/ **`extract_ideas`**（15 词/条）/ **`extract_main_idea`** / **`extract_recommendations`**（只抓可操作建议）
- **`analyze_claims`** — 对「论断」逐条评级，给证据/反驳/逻辑谬误/最终建议——适合处理**观点类**内容

**链接**：
- 主仓 https://github.com/danielmiessler/fabric
- pattern 全表 https://github.com/danielmiessler/Fabric/blob/main/data/patterns/pattern_explanations.md
- `extract_wisdom` 源码 https://github.com/danielmiessler/Fabric/blob/main/data/patterns/extract_wisdom/system.md

## 2 · 三空白 → 抄谁 → 怎么适配

### 空白① 提取什么 ← extract_wisdom 硬约束 + 第二大脑框架

我们的六维是好骨架，缺的是「每维要几条、多细、验收标准」。补法：
- 给六维**每维挂数量/字数约束**（学 extract_wisdom）：如「方法步骤 3~7 条、每条一个动词开头」「边界反例至少 1 条、写清失效条件」。
- 存的时候就问「**未来的我要用它做什么**」（BASB：蒸馏为复用/表达服务，不为存而存）。
- 每条 idea **原子化 + 用自己的话**（Zettelkasten）：一条只装一个想法，讲不清=没懂（Feynman 验收）。

### 空白② 打分 ← fabric rate_content 当门槛 + LLM-as-judge 单维度小分

`rate_content`（[system.md](https://github.com/danielmiessler/Fabric/blob/main/data/patterns/rate_content/system.md)）的真实评分逻辑，可直接抄成入库门槛：
- **打标签**：给内容打最多 20 个单词标签
- **两个因子**：① idea 密度（<10 差 / 11~20 好 / >25 优秀）② 与你关心主题的契合度
- **S/A/B/C/D 五档**：S=18+ ideas 或强主题匹配 → 逐档递减到 D=少量优质且几乎不匹配
- **1~100 数值分**：综合 idea 数量 × 质量 × 主题匹配

**适配**：把「主题契合度」的主题词换成你飞轮的主题清单；五档当「**存/缓/弃**」门槛（S/A 精读入库、B 存草稿、C/D 丢）；数值分用来排优先级。这直接补上收件箱「三态无价值维度」的缺口。

**进阶（LLM-as-a-judge 共识，来自 Appen + 学术）**——想让打分靠谱，别做「一个综合分」：
1. **一个 rubric 只评一个维度**；把「准确/有用/清晰/深度」合成一个分会评得不稳。
2. 每个维度写清 **维度定义 + 每档分数的文字描述 + 每档一个例子**（不是只给「1-5 分」）。
3. 用**证据型**标准（有无引用/数字/逻辑有序），别用「写得好不好」这种模糊形容词。
4. 给**参照样本**做相对判断，比纯 rubric 更准（纯 rubric 易手松、分数扎堆）。
5. 攒 **~20 条你亲手判过的样本**当校准集，对比 LLM 分反复改 rubric。
- 建议维度集（选 3~4 个即可）：**信噪比 / 洞见密度 / 对我的相关性 / 可行动性**，加权求和。
- 链接：https://www.appen.com/llm-as-a-judge-rubric-design · https://www.appen.com/llm-evaluation-rubrics · 信噪比框架（Ai2）https://allenai.org/blog/signal-noise

### 空白③ 提示词工艺 ← Anthropic 结构化抽取骨架

把内联字符串换成规范模板。Anthropic 官方结构化抽取要点：
1. **四段 XML 骨架**：`<task>` / `<themes>`（你的主题词表）/ `<input>`（待处理内容）/ `<output_format>` 分区隔开——单这一条就能把乱输出变结构化。
2. **JSON schema 卡死要抽的字段**，越具体越好。
3. **few-shot 精选而非堆砌**：从 1 个规范例子起步，不够再加；放少量典型样本，别塞边缘 case。
4. **评分类任务内嵌明确 rubric + 每档判据**（呼应空白②）。
5. context「信息足但紧凑」（tight but informative）。
- 链接：https://claude.com/blog/best-practices-for-prompt-engineering · https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents

## 3 · 方法论框架表（决定「提取什么 / 怎么结构化」）

| 方法 | 对「提取什么/怎么结构化」的一句精华 | 链接 |
|---|---|---|
| **BASB / CODE**（Tiago Forte） | Capture→Organize→**Distill**→Express；存时就想「未来的我要用它做什么」，不为存而存 | https://www.buildingasecondbrain.com |
| **Progressive Summarization** | 分层加压：原文→高亮→给高亮再高亮→一句话；**只在重读用到时才往下压一层**，避免一次性过度加工 | https://fortelabs.com/blog/progressive-summarization-a-practical-technique-for-designing-discoverable-notes/ |
| **PARA** | 按「可行动性」而非主题组织；存时先问「这服务于哪个正在推进的东西」 | https://fortelabs.com/blog/para/ |
| **Zettelkasten / 原子笔记** | 一条笔记一个想法、用自己的话、必须建链接；价值在**连接密度**不在收藏量 | https://zettelkasten.de/atomicity/guide/ |
| **Cornell** | 三分页：线索栏（写成**问题**）/ 笔记栏 / 底部总结栏——强制为每条内容产出「提问」和「一句总结」 | https://web-books.com/take-notes-books/ |
| **Feynman 技巧** | 验收标准=能用大白话讲清；讲不清处就是没真懂、需回原文 | https://fs.blog/feynman-technique/ |

**综合适配**：单条蒸馏卡可把这几家缝在一起——顶部一句 **Feynman 式大白话总结**（懂没懂的验收）+ 一个 **Cornell 式「它回答了什么问题」** + 正文 **Zettelkasten 原子化的 3~5 条 idea** + 底部 **CODE 式「未来用途/连到哪个项目」**；重加工留给重读时（Progressive）。

## 4 · 骨架参考（若日后要把蒸馏做成系统）

- **Karpathy llm-wiki 模式**（方法论，本机已装同款 `llm-wiki` skill）：三层 `raw/`（不可变原始源）+ `distilled/wiki/`（LLM 生成）+ `CLAUDE.md`（schema/规则）；三操作 `ingest / query / lint`。**最值得抄的是「增量维护 + lint 健康检查」**——不是每次从零 RAG，而是让 agent 持续把新源并进已有页并做一致性体检。
  - 参考实现：https://github.com/nashsu/llm_wiki · https://github.com/lucasastorian/llmwiki（MCP 接 Claude）· https://github.com/Astro-Han/karpathy-llm-wiki（含 citations + linting）
- **joshylchen/zettelkasten**：把 Zettelkasten 做成 AI 工作流 **CEQRC = Capture→Explain→Question→Refine→Connect**，含「智能链接发现」。这套五步可直接抄成蒸馏 pipeline 的阶段名。https://github.com/joshylchen/zettelkasten
- **Khoj / Reor / Quivr / Obsidian+AI 生态**：共同可抄的是「drop 任意源 → 自动抽要点 + **建双链** + 归档为你拥有的纯 Markdown」，尤其**自动建立笔记间连接**（价值最高、最难手动做）。

## 5 · 推荐最小落地路径（+ 心法约束）

最省事的起步，**不 fork 整个 fabric，只挑 5 个 pattern** 汉化 + 换成你的飞轮主题词：

| pattern | 补哪个空白 | 用途 |
|---|---|---|
| `extract_wisdom` | ① | 定单条内容的默认结构骨架（含硬约束） |
| `rate_content` | ③ 打分 | 定「存/缓/弃」入库门槛 |
| `summarize_micro` | 结构 | 卡片级极简蒸馏 |
| `analyze_claims` | 提取 | 观点类内容逐条评级 |
| `extract_recommendations` | 提取 | 抓可执行行动项 |

外层若要成系统，再套 llm-wiki 的 `raw/distilled/schema + ingest/query/lint` 骨架；打分先做 §2-② 的 3~4 个单维度小分。

**⚠️ 心法约束（别一上来就造引擎）**：按 [开发心法-多维思维总纲.md](../principles/开发心法-多维思维总纲.md) 的「人在环中门 + 频率门」——
- **打分自动化 = 让后端替你判「什么有价值」= 替我思考**，撞人在环中门；且没触真实摩擦就上重功能，撞频率门。
- 稳妥顺序：先把**方法论 + 提示词模板**沉淀成文档/模板文件（便宜、可逆），**打分先当「你手动套用的 rubric」跑**；跑顺、确实嫌烦了，再谈半自动。
- 两个待决先记着：① `creator-video-decoder` 断链拿什么替；② 六维抽成单一权威源（配置/文档），消灭 `distill.js:18` 硬编码与 7 维漂移。

### 6.4 结论与建议形式

1. **装一个（补最大缺口）**：chubbyskills 的 `bilibili-transcribe`，**只走字幕路径**（装 yt-dlp），语音识别依赖不装。装法按记忆纪律：先 clone 到 `/home/dev_st/桌面/comtools/tmp/` 核对 → 把 `bilibili-transcribe/` + `chubby_common/` 落到 skill 目录 → `platforms.js` B 站条目回填 `skill`。守宪章：可撤回（删目录即回滚）、无新构建步骤、离线可用（字幕抓取需网）。
2. **抄两处进六维模板**（不装）：second-brain-os 的 Calibration（限概念页数量、取材不压缩）；claude-obsidian 的 claim ledger（核心观点写成可证伪断言，出处带独立信源数）。lifeos 的「反共识观点必答」放进「核心观点」约束里，先不加第七维。
3. **只读借鉴 nuwa 的 4 份文档 + 1 个脚本，正对 ADR 0009 Phase 3「六维模板做成 distill skill」**（MIT，clone 到 `/home/dev_st/桌面/comtools/tmp/` 读，不装）：① `references/fidelity-scorecard.md` 的「评分 agent 与产出 agent 分离」铁律 + 5 维 rubric → 套成六维卡质量卡（与 prompt 库刚加的「读者测试」自检同一原理：自评不可信）；② `references/skill-template.md` 与 Phase 3 的「模板 Section ↔ 填充来源」映射表 → 「把模板做成 skill」的落地范式；③ Phase 1.5 / 2.5 两个 CHECKPOINT + 「失败模式 → 降级路径」if-then 表（并行不可用→串行、上下文不足→分段续跑、调研文件即断点）→ 长视频蒸馏的工程骨架；④ `references/extraction-framework.md` 三重验证（跨域复现 / 生成力 / 排他性）+「矛盾不调和」→ 改造成「核心观点 vs 边界反例」筛选判据；⑤ `scripts/srt_to_transcript.py`（108 行纯标准库 SRT/VTT 清洗）→ 长视频取材直接复用。
4. **已装（2026-09-24）**：`cangjie-skill` → `.claude/skills/cangjie-skill/`，用途「把书 / 长视频转写稿蒸成 Skill 包」，与知识卡互补、不接线；其 RIA++ 六段 + 三重验证四档 + 晋级门 + DIGEST 自检是 ADR 0009 Phase 3 的首选参照（6.3c 与深层分析）。取材候选 #2：同作者 `video-downloader`（多平台含小红书/视频号，但重）——**2026-09-24 二选一已出对比（`视频取材skill-选型.md`）：推荐第 1 条的 chubbyskills，video-downloader 因仓内无许可证不采纳**；装不装仍待用户拍板。
5. **不装**：wiki / second-brain 类（与 llm-wiki 重叠）；lifeos（硬编码路径）；claude-obsidian 整套（重叠 + 不能单装）；nuwa-skill（元层、成本高、静默出网）；yourself-skill（不相关、无维护、隐私无防护）。
6. **仍无解**：小红书视频——chubbyskills 未覆盖；唯一覆盖者 `video-downloader` 被许可证卡住（见上条），llm-wiki 源表标 `manual_only`，维持「人工摘录」路径。
